## 絶対に守ること

## 3. カレンダーに書く
次の形のコマンドを単独で1回だけ実行する（許可設定に一致させるため、先頭からこの順のまま。`&&` `;` `|` `$(...)` や事前の `cd`・`source`・`export` を付けない。説明文はファイル経由ではなく、ダブルクォートの中に直接書く）:
```
gog --account yuki.katayama@fout.jp --gmail-no-send -j calendar create primary --summary "[作業] 今日のToDo" --from <対象日>T09:00:00+09:00 --to <対象日>T09:15:00+09:00 --send-updates none --transparency transparent --description "<説明文>"
```
説明文の形式（プレーンテキスト、各行は短く。手書きノートに写しやすいように。ダブルクォートと $ と ` は使わない）:
```
□ 1. <やること>（<相手>・<期限 or 経過日数>）
   <一言メモ: いまの状況や次の一手を1行で>
   <元のスレッド/メール/予定へのURL>
□ 2. ...
（件数の上限なし。了解済みで作業が残っているものは「作業: 〜・👍済」と書く）

生成: <時刻> / 載せた <件数>件 / Slack <件数>（完了で閉じた <件数>・了解済み <件数>）・Gmail <件数>・カレンダー <件数> を確認
判断に迷ったスタンプ: <あれば :名前: を並べる。なければこの行は省く>
```
- このコマンドが権限確認で止められた・拒否された場合は、`--summary` だけを `"[作業] 今日の5件"` に変えた同じコマンドを1回だけ実行する（こちらは許可設定に登録済み）。その場合は報告に「旧名で作成」と書く。
- 「ほかの候補」欄は作らない（全部を番号付きの本リストに入れる）。
- 一言メモは「〜の返信待ちで止まっている」「13時の商談前に確認」「金曜締切」のように、見ればすぐ動ける内容にする。
- Slack のリンクは permalink、Gmail は https://mail.google.com/mail/u/0/#all/<threadId>、カレンダーは htmlLink。
- どこかの取得が失敗したら、説明文の末尾に「⚠ <取得元> が取得できませんでした」と書く（黙って欠落させない）。
