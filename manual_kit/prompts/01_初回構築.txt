{{PRODUCT}} の「機能取扱説明書」を、資料を全部読み込んで一から作ってください。
フリークアウトの HAWK で作った取説と同じ方式です（下の「参考実装」）。
長い作業なので、最初に計画を5行程度で示したら、確認を待たずに最後まで進めてください。
判断に迷ったものは推測で埋めず「要確認」タブに起票して先に進んでください。

# ゴール
1. Google スプレッドシート「{{PRODUCT}} 機能取扱説明書マスター」を作業フォルダに作り、資料から全部埋める。これを「正」とする。
2. マスターから Google スライド「【下書き】{{PRODUCT}} 機能取扱説明書 v1（日付）」をスクリプトで自動生成する（手で作らない）。
3. 1〜2 をいつでも再実行できるよう、スクリプトと手順書（スキル）をリポジトリに保存する。

# 読む資料

## A. 渡す資料（全部読む。読んだものはすべて「ソース一覧」タブに登録する）
- 画面キャプチャ（{{SCREENSHOT_FOLDER}}）
  - 1枚ずつ中身を見て、どのメニューのどの画面かを判定し、画面ID を振る。作業フォルダ内に「スクショ_加工済み」フォルダを作り、「S-01_ログイン.png」のような名前でコピーを置く（元ファイルは触らない）。
  - メールアドレス・人名・アカウント名・ワークスペース名・広告アカウントID・クライアント名やブランド名を OCR で見つけ、サンプル表記（sample@example.com、サンプル広告株式会社 など）に置き換えた加工版を作る。画面ごとに追加ルールを足せるよう、ルールは JSON にしてリポジトリに置く。
  - 加工後は必ず1枚ずつ自分の目で見直す。残っていたらルールを足して作り直す。
  - 暗い余白・モーダルの背景・ブラウザ枠は切り落とす。
- 操作デモ動画（{{VIDEO_FOLDER}}）
  - ダウンロードし、ffmpeg で画面が切り替わったところのコマを切り出して読む。操作の順番・画面遷移・ボタン名・入力例を拾う。
  - 同じフォルダに文字起こしや台本があれば一緒に読む。Meet の録画なら同名の文字起こし Doc を探す。
  - 動画のコマはスクショの代わりに使わない（画質が粗く、実データが映る）。スクショが無い画面は「要確認」に「この画面のスクショが欲しい」と起票する。
- サンプルレポート（{{SAMPLE_REPORTS}}）
  - 全部読み、レポートの種類・ページ構成・各指標の意味・出力条件を、機能一覧のレポート章と FAQ に落とす。
  - お客様に見せてよい見本は {{SAMPLE_REPORT_PUBLIC}}。取説のレポート画面のページからリンクする。
- 既存資料（{{EXISTING_DOCS}}）
  - {{CANONICAL_DOCS}} は正本として他より優先する。古い記述（後のリリースで変わったもの）は新しい出典で上書きし、メモに「旧: …」と残す。

## B. 自分で探しに行く資料（読み取りだけ。投稿・送信・編集はしない）
- Slack: {{WATCH_CHANNELS}} の過去 {{LOOKBACK}} 分を、スレッド返信まで全部読む。さらにワークスペース全体を {{KEYWORDS}} で検索し、他のチャンネルで出た仕様の回答・リリース告知・お客様からの質問も拾う。DM は読まない。
- Gmail: {{KEYWORDS}} で検索。リリースノート、仕様の回答、お客様からの操作の質問を拾う。
- 会議メモ: Drive の自動議事録（「Gemini によるメモ」など）と議事録 Doc を、本文の全文検索（fullText contains）で {{KEYWORDS}} を含むものから集める（日本語は title contains が効かないので fullText を使う）。オンボーディング・商談・社内の仕様会議の Q&A は FAQ の材料になる。文字起こしの誤変換は {{NAME_VARIANTS}} を手がかりに補って読む。
- Drive: 名前に {{PRODUCT}} を含む仕様書・リリースノート・スライド。
- 公開ページ: {{PUBLIC_PAGES}}
- リンク先の Docs / Slides / Sheets に仕様が書かれていれば、それも開いて読む。

# マスターシートの構成（このとおりに作る）

タブと列:
- README … 運用ルール（自由記述）。冒頭に「最新の下書きURL」と「本番の固定URL」を置き、スライドを作るたびに自動で書き換える。
- 機能一覧 … 機能ID / カテゴリ / 画面ID / 機能名 / できること / 設定項目・選択肢 / 何のため（目的） / 対応範囲 / 制約・注意 / 提供状態 / 承認 / 簡易版 / ソース / 初出日 / 最終更新日 / 承認日 / メモ
- サイトマップ … 画面ID / 階層1 / 階層2 / 階層3 / 画面名 / URLパス / 遷移元 / 遷移先 / この画面でやること / 関連機能ID / スクショ / 承認 / ソース
- 逆引き … UCID / カテゴリ / やりたいこと / 手順（概要） / 使う機能ID / 承認 / 簡易版 / ソース / メモ
- FAQ … FAQID / カテゴリ / 質問 / 回答 / 提供状態 / 関連機能ID / 承認 / 簡易版 / 出典 / 最終確認日 / 要確認 / メモ
- 更新履歴 … 検知日 / リリース日 / 種別（追加・変更・提供終了・不具合） / 対象ID / 内容 / 提供状態 / ソース / 反映状況 / 承認日
- 要確認 … QID / 対象ID / 確認したいこと / 誰に聞くか / 回答 / ステータス / 起票日
- ソース一覧 … SID / 種別 / タイトル / URL / 日付 / 重要度 / メモ
- 版管理 … 版 / 生成日時 / 種類（draft・prod・巡回・承認依頼） / スライドURL / PDF / 承認済行数 / メモ

値の決まり:
- 承認: 下書き（＝候補）/ 承認済 / 差戻し / 置換済 のプルダウン。
- 提供状態: 提供中 / 開発中 / 予定 / 未対応 / 提供終了 / 不明 のプルダウン。
- 簡易版: チェックボックス（よく使う基本機能だけ TRUE）。
- ID: 機能ID は F-カテゴリ略号-連番（例 F-RPT-003）、画面ID は S-連番、逆引きは UC-連番、FAQ は Q-連番。一度振った ID は変えない・使い回さない（やめた機能は提供状態を「提供終了」にする）。
- カテゴリと略号は、使う頻度の高い順に 8〜10 個決めて固定する。スライドの章もこの順に並ぶ。
- 1行目は固定表示、列幅・折り返しを整えて人が読める見た目にする。
- 初回に作った行は全部「承認=下書き」。{{OWNER}} がシートを見て直したあと「全件承認して」と言ったときだけ承認済にする。

# 書き方のルール
- 1行に1機能。「できること」は {{READERS}} が読んで分かる、です・ます調の1〜2文。社内用語・開発用語は使わない。
- 「ソース」列には必ず出典を書く（Slack の permalink、Doc の URL、資料名とページ）。出典が無いことは書かない。
- 資料同士で食い違ったら（例: 商談では「できない」、後の社内会議では「できる」）、新しい方を仮に書き、要確認タブに両方の出典つきで起票する。誰に聞くか（{{ASK_WHO}}）も書く。
- お客様の社名・個人名・メールアドレスはシートに書かない。機能の可否だけを書く。
- {{OUT_OF_SCOPE}} は取説に入れない。拾った場合は 承認=差戻し、メモ「取説対象外」。
- シートへの追記に values.append は使わない（チェックボックス列があると 1000 行目付近に書かれてしまう）。最終行を調べて行番号を指定して書く。TSV（1行目=列名）を読んで指定タブに追記するスクリプトを作って使う。
- 書く前に既存の行を読み、同じ内容があれば足さない（何度流しても重複しないようにする）。

# スライドの作り方
- Google Slides API（gws の presentations batchUpdate）を叩く Python スクリプトで、マスターから毎回まるごと作り直す。スライドを手で直さない（直したい点はマスターかスクリプトを直す）。
- 構成: 表紙（機能数・画面数・逆引き数・FAQ数）→ 目次と読み方 → 全体像（工程の流れと各工程の機能） → サイトマップ（画面構成と掲載ページ） → 最近の更新 → カテゴリごとの章（1画面1ページ: 左にスクショ、右にその画面の機能の表。【設定】【目的】【注意】） → 逆引き → FAQ。
- 載せるのは 承認=承認済 の行だけ。下書き版は 開発中・予定 も載せてよい。本番版は 提供状態=提供中 だけ。
- 下書きは版ごとに別ファイル（v1, v2, …）。作るたびに版管理タブに1行足し、README の最新 URL を書き換える。
- 本番版は {{READERS}} に渡す固定 URL。URL を変えず中身だけ上書きし、作り直すたびに PDF を日付つきで保存して版管理に残す。今回は本番版を作らない（{{OWNER}} の指示があったときだけ作る）。
- 非公開の Drive 画像は Slides API から直接読めないので、pptx を経由して取り込むなどの回避を入れる。
- デザインは {{BRAND}}。文字が枠からあふれるときは自動で文字を小さくする。「…」で切らない。

# やってはいけないこと
- 承認列を自分の判断で「承認済」にしない。
- 本番スライドを作らない・作り直さない。
- Slack・メールに書き込まない（この回の投稿はゼロ）。
- マスターと自分で作ったファイル以外の Drive ファイルを編集しない（元資料は読むだけ）。
