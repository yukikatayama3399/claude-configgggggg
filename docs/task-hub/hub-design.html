いま、ボールを持っているのは誰か。

Slack・Gmail・カレンダー・Drive の実データ（直近4〜7週）を読んで、片山さんの毎日の動きに合わせたハブを設計しました。中心にあるのは「やることリスト」ではなく、すべての依頼とやり取りを「自分 / 相手 / AI」のどこにボールがあるかで管理するという考え方です。目の前には自分ボールだけが出ます。

並べる単位は会社ではなく人とスレッドです。「誰と」「最後に話したのはどっちか」「何日経ったか」の3つで並べます。Slack の依頼の6割以上は社内からで、会社に紐づかないためです。会社名はタグとして付けます。

「通知を増やす」は一度失敗している DESIGN RULES

いまのダイジェストが読まれないのは、片山さんの怠慢ではなく作りの問題です。同じ依頼を何度も知らせるだけで、その場で片付ける手段がなく、終わっても自動で消えない。だから次の5つを守ります。

1件は1回だけ出す同じ依頼は1つのボールにまとめる。再通知はしない。期限が近づいたら並び順が上がるだけ。
その場で片付く返信の下書き、予定の仮押さえ、シートへの記入まで、ボールを開いた画面で終わらせる。別アプリへ飛ばさない。
勝手に閉じる自分が返信した、他の人が答えた、✅が付いた、予定が終わった。こうした事実を見て自動で消す。
カレンダーは今のまま「[作業]」の書き方を変えなくていい。ハブが読み取り、完了したら予定のタイトルに ✅ を書き戻す。
送るのは自分AIが作るのは下書きまで。メールも Slack も、送信は必ず片山さんの1クリック。
止まったら目に見える「最終取得 ○分前」を常に表示する。連携が切れたらカレンダーに赤い予定を入れて知らせる。106日気づかない状態を二度と作らない。
声でそのまま入る入力欄は普通のテキスト欄を1つだけ置く。Aqua Voice で話した内容がそのまま入り、履歴からコピーして貼り付ける手間をなくす。書式も専用の記法も要らない。
足す前に止める今ある自動ダイジェスト3本は止めて、この1本に置き換える。見る場所を増やさない。

Fable によるレビュー SECOND OPINION

最初の案を Fable にレビューさせました。結論は「このままだと、すでに無視されているダイジェストの豪華版になる」。指摘を受けて、軸・段階・ノートの扱いを変えています。

使われなくなる筋書き

  • 見ない場所が1つ増えるだけ。自分宛ての自動投稿を見ない習慣がすでにできている。
  • 静かに止まる。常時稼働の母艦が止まっても気づかず、古いデータを出し続けて信用をなくす。
  • 繰り越しが雪だるまになる。毎夕10件の判断を求めると全部繰り越され、翌朝50件になって見なくなる。
  • 分類ミスで元のアプリに戻る。cc 型のメンションや複数社のチャンネルを一度でも取り違えると、Slack を直接見る生活に戻る。
  • 会話の画面が重い。ボールごとに AI と会話するのは、ノートと Slack を直接見るより遅い。

反映したこと

  • 並べる単位を会社から「人 × 最後に話したのは誰 × 経過日数」に変えた。会社はタグ。
  • 商談だけは段取りが決まっているので、ステージで管理する（仮押さえ → 前日 → 予習 → 商談 → お礼 → フォロー）。
  • 完了は行動から自動で判定する。片山さんに完了ボタンを押させない。
  • フォーム営業の本物の返信を拾う機能は、小さくて価値が一番高いので最初に作る。
  • 手書きノートを正とする。ハブが追うのは、ノートに載らないもの（相手ボール、cc 型メンション、埋もれた返信）。
  • 画面を作るのは、1本の通知が実際に読まれて行動に結びつくと数字で確かめてから。

作る順番と、次に進む条件 PLAN

作らないもの OUT OF SCOPE

  • アプリ内ブラウザで Gmail や Slack を開くこと。どちらも埋め込みを禁止しているので、中身を読み込んで表示し、必要な時だけ元のアプリで開くリンクにします。
  • カレンダーの代わりの予定画面。予定は Google カレンダーのまま。
  • メモアプリ。メモは顧客フォルダの Doc に書き、ハブはそれを表示するだけ。
  • 自動送信。どの段階でも入れません。
  • プライベートの予定のタスク化。「[Private]」は読まない。
  • 「AI副社長」による全自動の振り分け。まずボール1件ごとの AI が当たり前に使えてから。
