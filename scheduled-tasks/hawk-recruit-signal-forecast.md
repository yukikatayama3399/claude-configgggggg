## 3. URL収集（サイト・フォーム・メールを埋める）の見込み

### ここが律速

| 制約 | 値 |
|---|---|
| WebSearch上限 | **1セッションあたり200回** |
| 1社あたりの検索 | 1回 |
| → 1セッションの処理上限 | **約200社** |
| 実測の1回あたり処理数 | **約95社**（46→140社の実績） |
| 発火頻度 | 毎時（1日24回、毎回新しいセッション＝新しい200回枠） |

| 期間 | 見込み |
|---|---|
| 1時間 | 約95社（実測） |
| **1日** | **約2,280社**（95×24。理論上限は4,800社） |
| 1週間 | 約16,000社 |

### 並列化は効かない（実証済み）
WebSearch の200回上限は**セッション全体で共有**され、サブエージェントに分けても総量は増えない。
10体並列で投入したところ、合計200回を数分で使い切って半分しか処理できなかった。
**増やせるのはセッション数（＝発火回数）だけ。**

## 5. 最終的にフォーム送信できる社数

全社のURLが取れるわけではない。**2026-08-19に60社を実処理して測った歩留まり**:

| 段階 | 実測 | 率 |
|---|---|---|
| 処理した社数 | 60社 | — |
| サイトURL取得 | 51社 | **85%** |
| フォームURL取得 | 41社 | **68%** |
| Eメール取得 | 13社 | 22% |
| 特定できず（要確認/社名非公開） | 9社 | 15% |

既出除外の通過率は別途実測で **56%**（フォーム送信用88社 → ミラー49社）。

### 逆算した最終見込み

```
2,093社 × 0.68（フォームURL取得率） × 0.56（既出除外を通過）≒ 780社
```

**推定780社前後**が最終的にフォーム送信可能になる。

当初は「フォーム取得率90%」と見積もって1,000〜1,100社としていたが、
実処理してみると68%だったため下方修正した。
Eメールに至っては22%しか取れない（検索スニペットに載っている会社が少ない）ので、
**メール配信を主軸にするのは現実的でない。フォーム送信が主経路になる。**

### リストが増えても送信可能数は比例しない
除外プールが13,949社あり、リストが積み上がるほど既出率は上がる。
既出除外の通過率56%は**今後さらに下がる**見込み。

## 6. 数字が変わったら疑うこと

| 症状 | 疑う原因 |
|---|---|
| 日次の新規が142社から大きく外れる | 収集キーワードの変更、求人ボックスのセレクタ変更、ledger突合の破損 |
| URL収集が1時間あたり95社を大きく下回る | WebSearch枠の消費増（1社2検索以上している）、ルーティンの途中失敗 |
| フォーム送信用が増えない | サイトURLは取れているがフォームURLが取れていない。検索クエリの見直し |
| ミラーが増えない | IMPORTRANGE がタブ改名で壊れた（`Unable to parse range` が出る） |
