# find_contact_forms.py — 問い合わせフォームURLの到達確認付き特定

`生収集_0804`（486社）のフォームURLを埋めるスクリプト。**会社Macで動かす前提。**

## なぜローカルで回すのか

Claude Code on the web のクラウドセッションは外部サイトへの egress が遮断されている。
`curl` も WebFetch も企業サイトに届かないので、**URLを見つけても叩いて確かめられない**。
Web検索だけで埋めると「検索結果に出てきたから正しいはず」の未検証データが残る。

会社Macなら実際にHTTPで叩ける。`200` が返ったURLだけ採用できるので精度が段違いに高い。
しかも**このスクリプトはLLMを一切使わない**（ただのHTTPクライアント + 正規表現）ので、
トークンを消費しない。

## 動かし方

```bash
cd ~/path/to/claude-configgggggg

# 1) まず20社で試運転（書き込みなし）
python3 find_contact_forms.py --limit 20

# 2) 全社スキャン（まだ書き込みなし。結果だけ見る）
python3 find_contact_forms.py

# 3) 納得したらシートに反映
python3 find_contact_forms.py --write

# フォームURLがまだ空の行だけやり直す
python3 find_contact_forms.py --write --only-missing
```

依存は標準ライブラリだけ。`pip install` 不要。Python 3.9 以上。
前提として `gog` が使えること（`gog auth list` でアカウントが出れば OK）。

## 何をしているか

1. `gog` でシートを読む
2. 会社URLのトップページを取得して**生存確認**（死んだドメイン・404を検出する）
3. HTML内のリンクから「お問い合わせ」導線を探す
   - アンカーテキスト（お問い合わせ / 問合せ / contact / inquiry …）と href パターンで加点
   - 採用ページ・プライバシーポリシー・PDF・mailto は除外
4. リンクが無ければ `/contact/` `/inquiry/` など定番パスを実際に叩く
5. 候補ページに `<form>` や「送信する」「必須項目」があるかで**フォームページかどうか確認**
6. `--write` のときだけ D列（フォームURL）と I列（要確認）に書き戻す

`formrun` や HubSpot など外部ASPのフォームも拾うが、その場合は I列に
「フォームが外部ASPドメイン」と注記が入る。

## 中断・再開

結果は `.contact_form_cache.json` に逐次保存される（20社ごと）。
Ctrl-C で止めても、同じコマンドを打ち直せば済んだ分は飛ばして続きから走る。
最初からやり直したいときだけ `--fresh`。

## 相手のサーバへの配慮

- 同一ホストへの連続アクセスは1秒あける
- 並列は既定8（`--workers` で変更可。上げすぎない）
- タイムアウト15秒、本文は600KBで打ち切り
- ブラウザと同じ User-Agent を送る

## このスクリプトで埋まらないもの

**会社URL自体が無い133社**は対象外。トップページが無ければ辿れない。
こちらは検索で特定するしかないので、クラウドセッション側の仕事として残っている。

I列に出る注記の意味:

| 注記 | 意味 |
|---|---|
| `会社URLなし（先に検索で特定が必要）` | C列が空。このスクリプトでは埋まらない |
| `トップページに到達できず（404等）` | **収集した会社URLが間違っているか、サイトが消えている** |
| `フォーム未発見（電話/メールのみの可能性）` | 到達はしたがフォームが無い。電話/メール窓口かもしれない |
| `フォームが外部ASPドメイン` | formrun等。使えるが送信先が別ドメイン |

「トップページに到達できず」が出た行は、**フォーム以前に会社URLが誤っている**ということなので、
そこは優先して直したほうがいい。
