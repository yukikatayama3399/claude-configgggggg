# HAWK 議事録作成 標準ワークフロー

商談が終わったあと、散らばっている情報（Gemini 自動メモ・片山さんの口述メモ・カレンダー）を
1本の読める議事録に束ね、顧客フォルダの正しい場所に置くまでをやりきる。

議事録は「あとで自分が読み返すため」だけでなく「社内で論点を共有し、宿題を回すため」のもの。
だから**論点と宿題が最初に目に入る構成**にし、**確からしさの違いを潰さない**のが肝になる。

## 固定値

- 親フォルダ「10_顧客」ID：`1Zcuk8SMcL8PQoymujhntAK3eAD2RUjbB`
- 格納先：`10_顧客 / <NN>_<社名> / 1_議事録`
- ファイル名：`議事録_MMDD_<社名>様商談`（内容が商談でなければ `議事録_MMDD_<社名>様_<会議名>`）
- ツール：`gws`（Drive/Docs/Calendar の生API）と `gog`（読みやすい出力）。どちらもセットアップ済み。

## Step 1: 対象の商談を特定する

カレンダーで日時・出席者を確定させる。口述メモは記憶頼りで日時や参加者が抜けやすく、
ここを固めておかないと「誰が言ったのか」が曖昧な議事録になる。

```bash
gws calendar events list --params '{"calendarId":"primary","timeMin":"<YYYY-MM-DD>T00:00:00+09:00","timeMax":"<翌日>T00:00:00+09:00","maxResults":50,"singleEvents":true,"orderBy":"startTime"}'
```

同じ日に複数の商談があると、口述メモの内容が別案件と混ざりやすい。
**参加者リストは案件の切り分けに効く**ので必ず確認する（誰が同席していたかで、どの案件の話か判別できる）。

## Step 2: 素材を集める

1. **Gemini 自動メモ**（あれば最優先の一次情報）。Doc URL を渡されていればそれを読む。
   渡されていなければ Drive で探す。タイトルは `<会議名> - YYYY/MM/DD HH:MM JST - Gemini によるメモ`。

   ```bash
   gog --account yuki.katayama@fout.jp docs cat <docId>
   ```

2. **口述メモ / チャットの貼り付け**。音声入力由来なので固有名詞が崩れる前提で扱う
   （人名・社名・製品名は Gemini メモやカレンダーの表記を正とする）。

3. 必要なら過去の議事録・メール・Slack。ただし本題から離れるので、論点に直接効く場合だけ。

## Step 3: 素材を突き合わせ、確からしさで仕分ける

これがこのスキルの一番の仕事。3つに分けて扱う。

- **両方に出てくる／Gemini メモにある** → 本文に事実として書く
- **口述メモにしかない** → 書いてよいが、出典を「備考」に明記する。
  断定できない固有名詞や URL は「未確認・要確認事項」に置き、本文で決定事項のように書かない
- **どちらにも無い推測** → 書かない。書くなら「（片山所感）」と明示する

音声入力の聞き間違いは実際に起きる。人名（例：荻田／荻谷）、社名、製品名が食い違ったら
**Gemini メモとカレンダーを正とし、チャットで一言指摘する**。黙って直すと次回も同じ間違いが再生産される。

同じ日の別商談の宿題が混入していないかも必ず見る。参加者・親会社名・先方担当者名で切り分け、
別件と判断したものは「備考」に「これは○○様側の宿題」と書いて隔離する。

## Step 4: 本文を書く

`assets/template.txt` を雛形にして、記法のプレーンテキストを書く。記法は Step 5 のスクリプトが解釈する。

```
══════════════════════════
【<正式社名>様 <会議名>】議事録
══════════════════════════

日時 ：2026/09/07（月）16:00〜17:00（オンライン／約60分）
参加者：
・フリークアウト（FO）：片山、中西、小瀬
・<正式社名>：荻谷拓真 様（集客戦略部）
目的 ：<この打ち合わせで何をしに行ったのか>

■ 概要
・<結論と論点を4〜6行。ここだけ読めば意思決定できる密度にする>

■ <最大の論点>【最大の論点】
▶ <小見出し>
・<箇条書き>

■ ネクストアクション
［先方］<宿題>
［当社］<宿題>

■ 未確認・要確認事項
・<確からしさが足りないもの、次回聞くこと>

■ 備考
・<出典、別件との切り分け、断り書き>
```

書き方の指針:

- **セクション順は重要度順**。時系列ではない。「概要」の次は最大の論点。
  雑談や進捗共有は後ろに送る。読み手は上から数行しか読まないことがある。
- **1行1論点**。1行が長くなっても改行で割らない（Doc 側で折り返る）。逆に、
  1つの箇条書きに複数の論点を詰め込むと拾い落とされる。
- **数字は必ず具体で書く**。「上限が足りない」ではなく「Platinum の 200 に対して実質 400〜500 が必要」。
  社内で判断する人はこの差分だけを見る。
- **箇条書きの間に空行を入れない**。空行は `■` セクションの前だけ。詰めた方が視認率が上がる。
- リンクは `[ラベル](URL)` と書く。スクリプトがハイパーリンク化する（プレーン URL のまま残さない）。
- ネクストアクションは `［先方］`／`［当社］` を行頭に置く。誰の宿題かが縦に揃って見えるのが目的。

## Step 5: Doc を作って組版する

格納先フォルダを特定する（社名でヒットしないことがあるので、`10_顧客` 直下を一覧して目視で拾う方が速い）。

```bash
gws drive files list --params '{"q":"'\''1Zcuk8SMcL8PQoymujhntAK3eAD2RUjbB'\'' in parents and trashed = false","fields":"files(id,name)","pageSize":200}'
gws drive files list --params '{"q":"'\''<顧客フォルダID>'\'' in parents and trashed = false","fields":"files(id,name)"}'
```

顧客フォルダが無ければ `hawk-customer-folder` スキルで先に作る（勝手に別構成で作らない）。

Doc を作り、スクリプトで流し込む。

```bash
gws drive files create \
  --json '{"name":"議事録_MMDD_<社名>様商談","mimeType":"application/vnd.google-apps.document","parents":["<1_議事録のID>"]}' \
  --params '{"fields":"id,webViewLink"}'

python3 <skill>/scripts/gdocs_minutes.py --doc-id <docId> --body body.txt
```

スクリプトは既存本文を消してから流し込むので、**書き直しは同じコマンドを再実行するだけ**でよい
（`--keep` を付けると末尾に追記になる）。

## フォーマットの中身（スクリプトが担保している）

見た目は既存議事録に合わせてある。手で作り直す必要が出たときのために仕様を残す。

- Google の見出しスタイル（HEADING_n）は使わない。全段落 `NORMAL_TEXT`。
  見出しスタイルは前後に余白が入って間延びするため、階層は記号と太字で表す。
- 全段落に `indentStart = indentFirstLine = -63.7795pt` / `indentEnd = -65.3228pt` を当てる。
  マージン 72pt の内側からさらに外へ広げることで、本文幅がページ一杯になり1行あたりの情報量が増える。
- `■` と `▶` で始まる行だけ太字。`・` 行は素のまま。
- Docs API のインデックスは UTF-16 コード単位。Python の `len()` ではズレるので、
  リンク範囲の計算は必ず `utf16_len` を使う（`gdocs-hyperlink` スキルと同じ理由）。

## Step 6: 報告する

チャットに以下を返す。

- 作成した Doc のリンク（クリック可能な形で）と格納先フォルダ
- **素材どうしで食い違った点**（人名の表記ゆれ、別件の混入など）と、どちらを採ったか
- 「未確認・要確認事項」に落としたもののうち、本人に確認した方が早いもの

議事録を作ったこと自体より、**突き合わせて見つかったズレを伝える方が価値が高い**。
そこは黙って処理せず、必ず言葉にする。

## やらないこと

- メール送信・Slack 投稿・カレンダー変更（本スキルは Doc 作成まで）
- 素材に無い内容の創作。埋まらない項目は「未確認・要確認事項」に置く
- 顧客フォルダの新規作成（`hawk-customer-folder` の担当）
- 商談前のブリーフィング（`hawk-shodan-prep` の担当）
