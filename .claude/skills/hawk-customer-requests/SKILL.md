# hawk-customer-requests: 顧客からの要望まとめ 週次更新

## 目的

「こういうことをやってほしい」という顧客要望に対して「どんなクライアントがいたか」を
正の字方式（社名並記・社数カウント）で積み上げ、**社数が多い＝ニーズが強い要望**として
開発チームに還元する。最終的に毎週の HAWK 週報に「顧客からの要望まとめ」として載せる。

  過去7日間の全チャネルを横断収集して正本Docと週報メモのブロックを更新する。
- **水曜 10:00 JST**: HAWK週報 Routine（trig_01H9pNo2RxrpTioqPK3QV9yT）の手順4dが

## 収集（過去7日間・全チャネル横断）

1. **議事録**: gog で Drive を検索し、過去7日間に更新された HAWK 商談・定例の議事録を読む。
   ```bash
   gog --account yuki.katayama@fout.jp -p drive search \
     "fullText contains '議事録' and mimeType = 'application/vnd.google-apps.document' and modifiedTime > '<7日前RFC3339>'"
   ```
   title contains は CJK で効かないので fullText を使う。`fullText contains 'Gemini'` の直近更新Docも union する。
2. **Slack**: `mcp__Slack__slack_search_public_and_private` で過去7日の HAWK 関連
   （顧客名・「要望」「ほしい」「対応してほしい」「できないか」等）。顧客とのSlackコネクトchも必ず確認。
3. **メール**: `mcp__Gmail__search_threads` で過去7日の顧客とのやり取り（HAWK関連）。
4. **抽出基準**: 「現在HAWKに機能として存在しないが、あれば導入の意思決定を促進する要望」
   「こういうものはないか／こういうことをしたい、という声」。

## 正本Docへの反映ルール

書き込みは `gws docs documents batchUpdate`（正本はタブなし＝tabId不要）。**必ず先に全文を読む。**

1. **明細**: 既存 No. と重複する要望は新規Noを立てず、該当Noに
   「【MM/DD】社名（日付・出所）: 要旨」を1行追記（正の字方式）。
   新規要望は該当カテゴリ（要件整理・入稿／見積もり・提案／運用／レポート・ダッシュボード／
   クリエイティブ／媒体・外部連携／料金・プラン／管理・セキュリティ）の末尾に通し番号で追加。
2. **■ ニーズ集計サマリー**: カテゴリ別・社数の多い順。書式「・要望名（社名、社名、…）… N社 → No.X」。
   社数は明細から数え直して齟齬をなくす。
3. **■ 週次アップデート（最新の週が上）**: 見出し直後に今週ブロック「==MMDD週（M/D〜M/D）==」を挿入。
   各行「・【新規/追記】社名（日付・出所: 議事録/Slack/メール）: 要旨 → No.X」。
   0件の週は「==MMDD週== ・今週は新規要望なし」の1行のみ（サマリー・明細は触らない）。
4. **追加日ルール（重要）**: **新規追加・社数更新した行は、行の一番冒頭に【MM/DD】（追加日）を付ける。**
   サマリー・明細・週次アップデート・週報転記ブロックの全てで共通。

### 書式の保持（重要・2026-09-02 片山が手動整形済み）

**全文削除→再挿入は禁止。** 対象行のみのピンポイントな insertText／deleteContentRange に限る。
ページ設定（A4・余白）や既存行の書式・改行位置を変えない。
書式規約: タイトル行＝太字16pt／サマリー上側の━━線と「■ ニーズ集計サマリー」行＝太字／
サマリー内のカテゴリ見出し【〇〇の部】＝太字／それ以外＝標準。
挿入テキストは挿入位置の書式を継承するため、通常行が太字になったら updateTextStyle で
bold:false を、新カテゴリ見出しは bold:true を明示。**書き込み後に必ず読み返して確認する。**

## 週報への転記（2社以上の声）

サマリーで **2社以上** の要望は週報にも載せる。

- 転記先: 週報メモ `t.0` セクション6内の「■ 顧客要望サマリー（2社以上の声・週報共有用）」ブロックを
  正本の最新サマリーから抜粋して**差し替え**る（`gws batchUpdate`、`tabId: "t.0"`。このブロック以外は触らない）。
- カテゴリ見出しは正本・本番週報と同じ **【〇〇の部】** 表記。行の「→ No.X」は転記時に外してよい。
- **今週新規追加・社数更新した行は行頭（一番冒頭）に【MM/DD】を付ける。**
- 本番週報での最終形（片山が貼り付け）: 見出し「顧客からの要望まとめ」＋正本Docへのリンクチップ＋
  注記「※3社以上の案件のみ抜粋」。注記の文言はこのままだが、実運用では
  ※Meta社へ申請中・※リソクリ解約の決め手のような**特記事項のある2社案件も含めている**。
  転記ブロックは2社以上を全部載せ、取捨選択は片山が貼り付け時に行う。

## ルール

- 追記前に必ず既存内容を読み、重複追記しない（水曜は Routine が2本走るため特に注意）。
- 読み取りは gog／Slack・Gmail の MCP、Doc書き込みは gws（どちらもセッション開始フックで自動セットアップ）。
- 定期実行では書き込んだ内容をレポートに全文出す（あとから人が直せるように）。
