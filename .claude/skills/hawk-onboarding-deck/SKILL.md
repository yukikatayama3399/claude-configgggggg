# HAWK オンボーディング資料の生成

2026-10-08 の gaaboo 様オンボーディング用に作った資料をテンプレ化したもの。
**テンプレ**: 【テンプレ】HAWKオンボーディング資料（Meta／TikTok 接続）
https://docs.google.com/presentation/d/1yeE82wjfdoZk7zwcIa6sBSHH-d-k8quzdpIqFUbdJ5w/edit
（元にした実物: 【gaaboo様】… https://docs.google.com/presentation/d/1z6LnqTfWvXkLXYwkG5DIBNDo5hkzWwLMi4a5vAkCWng/edit ）

## 資料の構成（10枚）

| # | スライド | 中身 | 顧客ごとに変わるもの |
|---|---|---|---|
| 1 | 表紙 | HAWK オンボーディング／Meta・TikTok 接続セッション | 社名・日時 |
| 2 | 弊社担当者のご紹介 | 佐藤（執行役員）・杉浦（PdM）・片山（セールス） | なし |
| 3 | 本日のゴール | 接続完了の基準 3つ | なし |
| 4 | 本日のアジェンダ | 時間割＋つまずきポイント2つ | 日時・中間MTG/振り返り日 |
| 5 | ご準備いただいているもの | Meta/TikTok の事前チェックリスト | なし |
| 6 | オンボーディング（区切り） | STEP 1〜3 と開始時刻 | 時刻（開始時刻から自動計算） |
| 7 | 無料トライアル カレンダー | 3週間のマス目。開始・中間MTG・振り返り・最終日を色分け | 日付と色（自動で塗り直し） |
| 8 | トライアル中のサポート体制 | 窓口は片山／メール・Slack・電話／定期の接点 | 中間MTG・振り返り日 |
| 9 | 前回お伺いした内容のサマリー | 貴社の状況／**課題・懸念**／HAWKへの期待 を各3項目 | **全部**（ここが顧客ごとの本体） |
| 10 | 機能と料金体系 | 概要資料（HAWK Overview 202609版_ver2）の料金スライドの複製 | なし |

## 集める情報（spec.json）

例は `examples/gaaboo_20261008.json`。

| キー | 中身 | 取り方 |
|---|---|---|
| `client` / `client_short` | 「株式会社gaaboo」/「gaaboo」 | 申込書・メール署名 |
| `onboarding.date/start/end` | つなぎ込みの日時 | カレンダーの確定予定 |
| `trial.start` / `trial.end` | トライアル期間。省略時は start=つなぎ込み日、end=start+13日（2週間） | 案内メール |
| `mid_mtg.dates` | 中間MTGの候補日（1〜2日）。確定済みなら1日＋`time` | カレンダー／ユーザーに確認 |
| `review` | 振り返り面談の推奨日。省略時は最終日の前日 | 同上 |
| `prev_mtg` | 前回商談の日付（サマリーの見出し用） | 商談議事録 |
| `summary.situation` | 貴社の状況 ×3（`[小見出し, 本文]`） | 商談議事録・会社概要Doc |
| `summary.issues` | **課題・懸念** ×3（`[タイトル, 本文]`） | 商談議事録・先方メール（必ず入れる） |
| `summary.expectations` | HAWKへの期待 ×3（`[小見出し, 本文]`） | 同上 |
| `internal_notes` | 社内向けの**対応方針**（課題ごとにどう対応するか、即答NGの論点など） | 議事録・社内メモ。スピーカーノートに入るので先方には見えない |
| `folder_id`（任意） | 保存先フォルダ（顧客フォルダの 2_提案書 など） | |

**文字数の目安**（超えると枠からはみ出す）:
- 状況・期待の本文: 24字以内（2行）／小見出し: 10字以内
- 課題のタイトル: 14字以内／本文: 40字以内

材料は gaaboo のときと同じく、Gmail（商談お礼メールのスレッド・先方返信）、
Drive の商談議事録・会社概要Doc、カレンダーの確定予定から集める。
課題・懸念は推測で埋めず、議事録か先方の発言に出てきたものだけ書く。

## 手順

```bash
cd .claude/skills/hawk-onboarding-deck
# 1) spec を書く（examples/ をコピーして編集）
# 2) ドライランで日付とカレンダーの塗り分けを確認
python3 scripts/build_onboarding_deck.py spec.json --dry-run
# 3) 生成（テンプレを Drive でコピー → {{KEY}} 置換 → カレンダー塗り直し → ノート記入）
python3 scripts/build_onboarding_deck.py spec.json
```

4) **必ず見た目を確認する**。PDF で書き出して全ページを目視し、はみ出し・折り返しを直す。
```bash
gog --account yuki.katayama@fout.jp drive download <ID> --format pdf --out deck.pdf
pdftoppm -r 80 -png deck.pdf page
```
5) URL をユーザーに渡す。**共有設定は触らない**（共有はユーザーが判断する）。

スクリプトは「テンプレに見つからなかったキー」「置換されずに残ったプレースホルダ」があれば最後に出す。
出たらテンプレ側が編集されてプレースホルダが消えている可能性がある。

## テンプレを直すとき

- テンプレのスライドを直接編集してよい。ただし次は崩さないこと:
  - `{{CLIENT}}` `{{ONB_DATE_LONG}}` `{{ONB_DATE}}` `{{ONB_TIME}}` `{{T_START}}` `{{T_QA}}`
    `{{T_STEP1}}〜{{T_STEP3}}` `{{TRIAL_START}}` `{{TRIAL_END}}` `{{MID_MTG}}` `{{MID_MTG_SHORT}}`
    `{{REVIEW}}` `{{REVIEW_SHORT}}` `{{PREV_MTG}}` `{{SITU1..3(_L)}}` `{{ISSUE1..3_T/_B}}` `{{EXP1..3(_L)}}`
  - カレンダーのスライドは「角丸のマス 21 個＋各マスの中の日付テキスト（例 10/5）」で判定している。
    マスを減らしたり角丸以外の図形に変えると塗り直しが止まる。
  - サマリーのスライドは「お伺いした内容のサマリー」という文言でノートの書き込み先を探している。
- 実物（gaaboo の資料）を直してテンプレに反映したい場合は、テンプレを複製し直して
  プレースホルダを入れ直す（gaaboo の文言 → `{{KEY}}` の replaceAllText）。

## カレンダーの塗り分け

| 状態 | 色 | ラベル |
|---|---|---|
| 期間外 | 白・灰枠・灰文字 | なし |
| 期間内 | 淡緑 | なし |
| 開始日 | 濃緑 | 開始／本日（つなぎ込み日＝開始日のとき） |
| 中間MTG | 緑 | 中間MTG／候補日（候補2日）・中間MTG／11:00〜（確定） |
| 振り返り | 中緑 | 振り返り／推奨日 |
| 最終日 | 緑 | 予備日／最終日（振り返りが前日のとき）・最終日 |

週は月曜始まり。開始日の週の月曜から 3 週間（21日）を描くので、2週間のトライアルは曜日にかかわらず収まる。

## オンボーディング後のフォロー（gaaboo で実施した流れ）

1. **お礼メール**（テキストを作ってユーザーに渡す。送信はしない）
   - 本日のお礼 → トライアル開始できた旨 → いっぱい触ってほしい・気になることは気軽に連絡（メール／Slack／電話）
     → 次回（中間MTG）の日時と Meet URL → 結び
2. **中間MTGのカレンダー**
   - 予定に Meet が無ければ `conferenceData.createRequest`（`conferenceDataVersion=1`）で発行して URL をメールに入れる
   - 概要欄にトライアル期間・アジェンダ・連絡手段を書く（`sendUpdates=none`）。先方の招待追加はユーザーの指示があるまでしない
   - 概要欄は先方に見える前提で書く。社内事情（価格交渉・社内判断待ち等）は書かない
3. **議事録**: 文字起こし・音声メモが届いたら作る（届くまで待つ）

## 注意

- 料金スライド（10枚目）は概要資料の料金ページを要素ごと複製したもの。料金が改定されたら
  最新の概要資料から複製し直す（gaaboo のときは HAWK Overview 202609版_ver2 の22枚目）。
- 社内向けの話（価格の個別要望・UUUM 等の座組み・申込書の不備）はスライド本文に出さず、`internal_notes` に入れる。
