# drive-inbox-sort: マイドライブ直下の毎日振り分け

片山はダウンロード・アップロード・新規作成したファイルを、とりあえずマイドライブ直下に置く。
このスキルが1日1回それを正しい置き場所へ移し、直下を空に保つ。片山の事前確認は要らない（2026-10-20 合意）。

## 絶対ルール

1. **会議メモ・文字起こし・録音は、どこまでいってもマイドライブ**（`50_会議メモ`）。
   Gemini の自動メモ（「〜 - Gemini によるメモ」「メモ - 「〜」」）、Meet の録画・文字起こし、ボイスメモ、音声ファイルが対象。
   `drive_inbox.py move` もこれらを共有ドライブへ移そうとすると拒否する。
   一方、そこから**生成・整理した議事録**（「議事録_MMDD_〜」「【議事録】〜」など人や Claude がまとめたもの）は作成物なので共有ドライブへ。
2. **それ以外の作成物（HAWK の仕事で作ったもの）は共有ドライブ 07_HAWK 配下**。顧客ごとの資料・商談や打ち合わせのレポート・報告資料をマイドライブに残さない。
3. **共有ドライブへ入れたものは自分ではマイドライブに戻せない**（権限が「追加はできるが外へは出せない」）。
   しかも共有ドライブは BizAll メンバー全員から見える。中身を見ても行き先に確信が持てないものは**動かさずに報告**する。
   当て推量で共有ドライブへ入れるより、直下に1日残る方が安い。
4. ファイルを消さない（ゴミ箱にも入れない）。重複・空ファイルは `_削除候補` に入れるだけで、消すのは片山。
5. ファイルの中身は変えない。改名は「無題のドキュメント」等で中身が明確なときだけ（下の命名規則に沿う）。

## 手順

最初にリポジトリ直下で gog / gws が使える状態にする（Routine の指示にある準備手順）。以降の操作はすべて `drive_inbox/drive_inbox.py`。

1. `python3 drive_inbox/drive_inbox.py inventory` で振り分け対象を出す。
   固定フォルダ（00〜99・REGALCORE・_削除候補）とアプリが自動で使うフォルダ（Google Meet / Vids / Chrome から保存 / Gemini Gems）は最初から除外されている。
   0件なら「直下は空」で終了。
2. 1件ずつ行き先を決める。名前で決まらなければ `peek <id>` で中身の先頭を読む。顧客フォルダは `customers` で確認する。
3. `move <id> <DEST>` をまずドライランで出し、問題なければ `--apply` を付けて実行する。
   改名するときは `--name "新しい名前"`。フォルダは共有ドライブへ移すとき自動で「同じ構成を作って中身を移す」になる。
4. 新しい顧客で `10_顧客` にフォルダが無ければ、`mkcustomer <社名>`（ドライラン → `--apply`）で
   `NN_社名/1_議事録・2_提案書・9_契約書` を作ってから入れる（hawk-customer-folder スキルと同じ構成）。社名は敬称・法人格を除いた通称。
5. 報告（下記）。

## 行き先の決め方（上から順に当てはめる）

| 中身 | DEST |
|---|---|
| 会議メモ・文字起こし・録音（ルール1） | `50_会議メモ` |
| 中身がほぼ空の「無題」（inventory の `empty_untitled` が true で、`peek` しても本文が無いもの） | `_削除候補`（移動先に同じファイルが既にある重複は、どの DEST を指定しても move が自動でここへ回す） |
| 個人のもの（領収書・経費精算・名刺・ランチ/会食・私用・家族） | `90_個人` |
| REGALCORE / ADアラート / リーガルコア関連（副業・社外秘。HAWK ではない） | `REGALCORE` |
| Routine やスクリプトが読み書きする台帳・ログ・テスト用ファイル | `60_自動化データ` |
| 他部署・他プロダクトの媒体資料（GP / ASE / DOOH / alpaka / シネアド など。HAWK の作成物ではない受け取り資料） | `70_他部署・媒体資料` |
| 用途の分からないスクショ・画面録画 | `80_動画・スクショ素材` |
| 旧版・backup・draft の残骸で、正本が別にあるもの | `99_アーカイブ`（HAWK の作成物の旧版なら、正本と同じ共有フォルダ内の「旧版」系サブフォルダでもよい） |
| **ここから下は共有ドライブ 07_HAWK** | |
| 特定の顧客・見込み客向けの資料（提案書・アジェンダ・ヒアリングシート・見積・【〇〇様】入り） | `10_顧客/<NN_社名>/2_提案書`（`customers` の ID を使う） |
| その顧客との商談・打ち合わせの議事録（生成・整理版） | `10_顧客/<NN_社名>/1_議事録`。社名が特定できない・社内会議の議事録は `02_顧客会議ログ` |
| 申込書・NDA・契約書・利用規約 | 顧客別なら `10_顧客/<NN_社名>/9_契約書`、雛形や規約そのものは `06_契約書` |
| 電通・ADK など戦略パートナー向け | `10_戦略的パートナーシップ` 配下の各社フォルダ |
| UUUM 関連（社外秘） | `03_UUUM社外秘` |
| 架電前・商談前の会社概要リサーチ、商談準備メモ | `03_会社概要リサーチ` |
| アタックリスト・営業リスト・メール送付先・SF 棚卸し・商談ステータス表 | `03_セールス活動` |
| HIROGARU・フォーム営業の送信結果（result.csv 等） | `14_HIROGARU` |
| HAWK の概要資料・DealDesk 資料・料金・サンプルレポート（お客様に見せる汎用資料） | `01_概要資料` |
| テンプレ・手順書・デモ動画・レクチャー | `05_資料集`（動画は `05_デモ画面録画`） |
| 機能取扱説明書用のスクショ（名前が `S-数字` で始まる画像） | `05_取説スクショ`（HAWKマニュアル巡回 Routine が拾う） |
| 料金・事業計画・対応方針など戦略 | `04_ビジネス戦略` |
| 顧客要望・Q&A・FAQ | `09_顧客からのFAQ` |
| 週報・週次報告・定例用の差し込み資料 | `11_週次_Yuki` |
| 競合比較・競合調査 | `13_競合資料` |
| 紹介・パートナープログラム | `15_パートナープログラム` |
| ウェビナー・展示会・イベントの資料・バナー・録画・フォロー | `16_イベント・ウェビナー/<YYYYMMDD_イベント名>`（無ければ同じ構成で作る。既存の `20260929_HAWKウェビナー` は 01_本番資料 / 02_各社送付用資料 / 03_動画アーカイブ / 04_バナー・告知 / 05_フォロー / 99_ドラフト・旧版） |
| セキュリティチェックシート・技術資料 | `20_技術・セキュリティ資料` |
| どれにも確信が持てない | **動かさない**。報告の「要判断」に理由付きで載せる |

迷いやすい例:
- 「【〇〇様】HAWK_ウェビナー資料」→ 顧客名入りでもウェビナーの各社送付用なので `16_イベント・ウェビナー/…/02_各社送付用資料`。
- 「Allis志村様_〜」→ Allis はオーリーズ（`26_オーリーズ`）。顧客名の表記揺れは `customers` の一覧と突き合わせる。
- 中身が議事録でもタイトルが「無題のドキュメント」なら、`議事録_YYYYMMDD_社名様_内容` に改名してから入れる。

## 報告

最終回答（Routine では Slack DM にも同じ文面）を次の形で出す。移動0件・要判断0件の日は「直下は空（振り分けなし）」の1行だけ。

```
🗂 マイドライブ振り分け（YYYY/MM/DD）
移動 N件（共有ドライブ N / マイドライブ N）・削除候補 N件・要判断 N件
・<ファイル名> → <移動先のパス>
▼要判断（直下に残した）
・<ファイル名>：<迷った理由>
```
