# HAWK 議事録の作成・格納

打ち合わせのたびに **1回=1Doc** を該当顧客の `1_議事録` フォルダへ足していく。
過去の議事録は絶対に書き換えず、常に新規Docを追加する（フォルダ名順＝時系列ログになる）。

## 手順

### 1. 文字起こしを読む
- Doc の URL / fileId をもらったら `mcp__Google_Drive__read_file_content` で全文取得。
- Gemini自動メモ付きの場合、前半に「概要／決定事項／次のステップ／詳細」があり
  後半に生の文字起こしがある。**両方読む**。自動メモは要約が粗く、
  金額・期限・社内向けの判断など重要情報が落ちていることが多い。

### 2. 格納先フォルダを特定する
- 顧客フォルダは `10_顧客/<NN>_<会社名>/1_議事録/`。
- `mcp__Google_Drive__search_files` で
  `mimeType = 'application/vnd.google-apps.folder' and title contains '<会社名>'`
  → 顧客フォルダ → その配下の `1_議事録` の fileId を取る。
- 顧客フォルダが無ければ **先に `hawk-customer-folder` スキル**で箱を作る。
- 同フォルダの既存議事録を必ず一覧し、直近分を読んで
  「前回の保留事項」を今回の議事録に引き継ぐ。

既知のフォルダID（増えたら追記する）:

| 顧客 | 1_議事録 folderId |
|---|---|
| 株式会社リソースクリエイション | `1zppe5oX1htjcwvnyGMMhzBINj03zha4_` |

### 3. ファイル名
```
議事録_MMDD_<会社略称>様_<議題>
```
例: `議事録_0818_リソースクリエイション様_HAWK利用状況・継続意向ヒアリング`

- `MMDD` は打ち合わせ実施日（作成日ではない）。年をまたぐ運用が必要になったら
  `YYYYMMDD` に切り替える。既存分は改名しない。
- 既存フォルダの命名に揃える。過去は `議事録_0714_リソースクリエイション様商談（HAWKご案内）` の形。

### 4. 本文フォーマット
下記の見出し構成を固定で使う（既存議事録と揃えるため崩さない）。

```
══════════════════════════

**【<会社名>様 <議題>】議事録**

══════════════════════════

日時 ：YYYY/MM/DD（曜）（オンライン・Google Meet／約NN分）

参加者：

・フリークアウト（FO）：<氏名（役割）>

・<会社名>：<氏名> 様（<役割>）

目的 ：<この打ち合わせの目的>

**■ 概要**            … 太字ラベル付きで5〜7本。数字（体感効果・金額・期限）は必ず入れる
**■ 決定事項**        … 合意したこと。誰が何をいつまで、が判る粒度
**■ ネクストアクション** … ［担当者］ 内容 — 期限 の形。相手側タスクも書く
**■ 詳細**            … ▶ 小見出し単位で議論の流れを再現。相手の発言は「」で引用
**■ 社内メモ（FO限・対外共有不可）** … 条件付き（下記参照）
**■ 次回 / 保留事項**   … 次回MTGまでに動くもの・未決のもの
**■ 出典**            … 元文字起こしDocへのリンク
```

- 各行は `・` 始まり、行間に空行を1つ入れる（既存Docと同じ見え方になる）。

### 5. 「社内メモ」セクションの判断（重要）
商談の後半に **社外の方が退出したあとの社内会話** が含まれていることがある。
ここには値引き余地・解約リスク・交渉カードなど**対外NGの情報**が入る。

- 格納先フォルダの共有範囲を `mcp__Google_Drive__get_file_permissions` で必ず確認する。
- **社内（@fout.jp）のみ** なら `■ 社内メモ（FO限・対外共有不可）` として明示的に節を分けて記載する。
  交渉方針は落とさず残す（後で読み返す価値が最も高い部分）。
- **外部ドメイン／リンク共有が含まれる** 場合は、そのセクションを議事録には書かず、
  別Doc（社内フォルダ）に分けるかチャットで報告のみに留める。判断に迷ったらユーザーに確認する。

### 6. Doc を作る
**gog が使える場合**（ローカルMac等）はそちらを優先:
```bash
gog --account yuki.katayama@fout.jp docs create "<ファイル名>" ...
```

**gog が無い場合**（クラウドセッションで `GOG_CREDENTIALS_B64` 未設定など）は
Drive MCP で作れる。`contentMimeType: text/markdown` にすると
**太字・見出し・ハイパーリンクが実体として変換される**（`text/plain` はアスタリスクが literal になるので使わない）:

```
mcp__Google_Drive__create_file
  title: 議事録_MMDD_...
  parentId: <1_議事録 の folderId>
  contentMimeType: text/markdown
  textContent: <本文>
```

作成後は `mcp__Google_Drive__read_file_content` で読み返し、
太字が `**` のまま残っていないか・リンクが生きているかを確認する。

### 7. 報告
チャットには Doc URL と、決定事項／ネクストアクションのうち
**自分（片山）宛のもの・期限があるもの**だけを短く出す。全文は貼らない。

## やらないこと
- 既存議事録の上書き・削除・改名
- 元の文字起こしDocの編集
- 顧客への共有・送信（依頼された場合のみ別途）
