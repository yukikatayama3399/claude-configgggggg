# form-reply-triage: フォーム営業の返信トリアージ

## 背景（これが解く問題）

片山は他社の問い合わせフォームに HAWK の案内を送る outbound をやっている。
返信は1日に何十通も来るが、**大半は「お問い合わせありがとうございます」の自動返信**で
アクション不要。その中に月に数件、**人間が書いた「資料と料金を送ってほしい」**のような
**こちらにボールが返ってきた返信**が混ざる。これが自動返信に埋もれて見落とされる。

この Skill は、その「ボールがこっちにある返信」だけを拾って、
**Slack DM で叩き起こし、返信内容を Gmail 下書きに入れておく**。

## 手順

### 1. 対象スレッドを集める

```
in:inbox newer_than:3d -label:フォーム返信/要対応
```

`search_threads` で取得（pageSize 50）。`nextPageToken` が返ったら**2ページ目まで**は追う。

窓が3日あるのは、金曜21時から月曜9時までの間を月曜の初回で拾い切るため。
そのぶん同じスレッドを何度も見ることになるが、下の2つで二重通知は防がれる:

- **A 判定したスレッドには `Label_5`（要対応）を付ける**。次回はクエリから除外される。
- **最新メッセージが `SENT` ラベルのスレッドは無視する**（片山が返信済み＝ボールは相手側）。

### 1.5 読む量を絞る（コスト対策）

3日窓だと毎回50〜70スレッド返る。全部 `get_thread` すると重いので2段階で絞る:

1. **snippet で明らかな B を落とす** — メルマガ、セミナー告知、配信不能通知、
   カレンダー招待、ログイン通知、「お問い合わせありがとうございます。担当者より
   ご連絡します」だけの自動返信。ここで大半が落ちる。
2. **残った全件を `get_thread`（messageFormat: PLAIN_TEXT）で本文まで読む。**
   snippet が自動返信の定型文で始まっていても、後ろに本題が続くことがある。
   **迷ったら読む。読むコストより見落としの方が高い。**

### 2. 仕分ける

**A: 要対応（こちらにボールがある）** — 以下のどれかに当てはまる:

- 資料・企画書・料金表の送付を求められている
- 商談・デモ・打ち合わせの日程を聞かれている、日程候補が提示されている
- 機能・価格・契約条件について具体的な質問が来ている
- 担当者に取り次ぐので詳細をくれ、と言われている
- 人間が書いた文章で、明らかに返事を待っている

**B: 対応不要** — 通知も下書きも作らない:

- 「お問い合わせありがとうございます。担当者よりご連絡します」だけの自動返信
- 「今回は見送らせていただきます」等のお断り（返信不要）
- メルマガ・セミナー案内・配信停止通知・配信不能通知
- 自分が送った outbound のフォーム控え（自動コピー）
- 既に片山が返信済みのスレッド（最新メッセージが `SENT` ラベル）

**判断に迷ったら A に倒す。** 見落とす方が、余計な通知1件より高くつく。

### 3. Gmail 下書きを作る（A のみ）

`create_draft` を使う。**送信は絶対にしない。**

- `replyToMessageId`: そのスレッドの**最新の相手メッセージ**の `id`
- `to`: 相手のアドレス
- `cc`: `hawk-sales@fout.jp`（フォーム営業の返信は必ず cc する運用）
- 本文の末尾に下の署名を必ず付ける

同じスレッドに既に下書きがある場合（`list_drafts` で `threadId` を確認）は
**新しく作らない**。Slack で「下書きは既にあります」とだけ伝える。

### 4. Slack DM を送る（A が1件以上のときだけ）

`slack_send_message` / `channel_id: U0B7FMCR8JU`（片山本人へのDM）。

**要対応が0件なら Slack は送らない。** 「0件でした」の報告も送らない
（通知が来た＝必ず何かある、という状態を保つため）。

書式:

```
📮 フォーム返信トリアージ（MM/DD HH:MM）— 要対応 N件

*1. 株式会社〇〇（担当者名）*
・相手の要求: 企画書と料金表を送ってほしい
・下書き: 資料・料金プラン案内テンプレで作成済み
・⚠️ 概要資料PDFの添付が必要
・https://mail.google.com/mail/u/0/#all/<threadId>

*2. …*
```

- 各件に必ず Gmail スレッドへの直リンクを付ける
- 資料送付テンプレを使った件には **⚠️ 概要資料PDFの添付が必要** を必ず入れる
  （PDFは下書きに自動添付されない。理由は下記）

### 5. ラベルを付けて締める

**A 判定したスレッドにだけ** `label_thread` で `Label_5`（フォーム返信/要対応）を付ける。
これをやらないと次回また同じ件を通知する。

B 判定にはラベルを付けない。毎回 snippet で落ちるだけなので安く、
片山の Gmail にゴミラベルが増えない。

### T2: 日程調整・デモ希望

T1 の料金ブロックを落とし、デモ予約リンクを主役にする。

「〇月〇日（〇）〇時でお願いできますでしょうか」と1つに絞る文面にする。

### T3: 個別質問への回答

テンプレを貼らず、質問に正面から答える文面を書く。
答えが社内情報を要して分からない項目は、**推測で書かない**。
その行を `【要確認: 〇〇】` と明示し、Slack DM でもその旨を伝える。

## 概要資料PDFを自動添付しない理由

実体は Google Slides:
`1DDY0AxIOoArf23EbnDwBpP4k8zqNPMmpECIB_0oU7YQ`
（`【概要資料】HAWK Overview 202609版 ※要PDF DL`）

PDF に書き出すと約6MB。`create_draft` の `attachments` は base64 文字列を
コンテキストに載せる必要があり、8MB超のテキストを毎回3時間おきに通すのは非現実的。
よって **添付は片山が送信前に手でやる**前提とし、
Slack DM に ⚠️ を出して忘れないようにしている。

## 絶対にやらないこと

- **メールの送信**（`send_message` / `reply`）。作るのは下書きだけ。
- 相手の要望を勝手に判断して条件（金額・納期・割引）を約束する文面を書く
- 分からないことを推測で埋める。`【要確認: 〇〇】` を使う
- 0件のときに Slack を送る

- インバウンド（HAWK の資料DLフォームから来たリード）は別スキル
  `hawk-inbound-lead` の担当。こちらは **outbound の返信** 専用。

## MCP コネクタが使えないときのフォールバック（Gmail のみ）

Routine のセッションに Gmail コネクタ（`mcp__Gmail__*`）が無い場合がある。
そのときは **gog で同じことができる**（SessionStart フックが毎回セットアップしている）。

```bash
A=yuki.katayama@fout.jp

# 検索（スレッド一覧）
gog -a "$A" gmail search 'in:inbox newer_than:3d -label:フォーム返信/要対応' -j

# 本文を読む
gog -a "$A" gmail get <messageId> -j

# 下書きを作る（送信ではない）
gog -a "$A" gmail drafts --help   # サブコマンドを確認してから使う

# ラベルを付ける
gog -a "$A" gmail thread modify <threadId> --add-label <labelId>
```

**`gog gmail send` は絶対に使わない。** 必要なのは drafts だけ。
安全側に倒すなら `--gmail-no-send` を付けて実行する。

Slack には CLI のフォールバックが無い。Slack コネクタが無い回は、
下書きとラベル付けまでを済ませ、**セッションの出力に要対応の一覧を必ず書き残す**
（片山が Routine の実行結果を見れば追えるようにする）。
