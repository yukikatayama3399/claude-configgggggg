# hawk-manual-update: HAWK 機能取扱説明書の巡回更新

## 全体像（2026-10-09 確定の運用）

- **正はマスターシート**（`hawk_manual/config.json` の `master_sheet_id`）。スライドは生成物なので直接直さない。
- スライドは2種類。どちらも **承認済の行だけ** で作る（候補＝承認待ちの行は載らない）。
  - **社内管理用の下書き版** … 版ごとに別ファイル（下書きv1, v2, …）。開発中・予定の機能も載る。
    `python3 build_slides.py draft --note "変更内容"` で次の版を作る。同じ修正回の中で作り直すときは
    `--same-version`。`draft_presentation_id` は常に最新版を指し、版管理タブに URL が残る。
  - **本番版（お客様送付用・固定URL）** `prod_presentation_id` … 承認済 × 提供中 の行だけ。URL は今後も変えず中身だけ上書き。
    **お客様に渡しているので、片山が「本番に反映して」と直接指示したときだけ** `python3 build_slides.py prod --archive` を回す。
    巡回・Routine からは絶対に回さない。
- 生成のたびに README タブの先頭（最新の下書きURL・本番の固定URL）が自動で書き換わる（`readme.py`）。
- 列定義は `hawk_manual/schema.py`。章の中の画面の並びは `build_slides.py` の `SCREEN_ORDER` / `SCREEN_CHAPTER`
  （片山が v4 で並べ替えた順を固定したもの）。

## 承認の流れ

```
新着を拾う → シートに「承認=下書き」（候補）で追記 → #hawk-sales-private に片山宛ての承認依頼を投稿
  → 片山が候補ごとに ✅ / ❌ を付ける（またはスレッドに「1,3 OK / 2 NG」と書く）
  → 次の巡回（または「承認分を反映して」の依頼）で、✅ は 承認済、❌ は 差戻し にして
    下書き版を新しい版で作り直す → README の最新下書きURLが更新される
  → 本番は片山の指示があるまで触らない
```

## 巡回の手順（月・木 8:52）

作業ディレクトリは `hawk_manual/`。

1. **後始末**: `python3 housekeep.py`（承認日の記入、同IDの古い承認済行を置換済に）
2. **前回の承認依頼を処理する**:
   - 版管理タブで 種類=`承認依頼` かつ メモに「未処理」とある行を探す（メモに Slack の ts と候補の一覧が入っている）。
   - `slack_read_thread`（channel `C0B8HGGC2PJ`、その ts）でスレッドを読み、候補ごとの返信に付いたリアクション
     （✅ `white_check_mark` / ❌ `x`）と、片山のスレッド返信（「1,3 OK」「2 NG」等）を読む。
   - ✅ の候補 → その行の 承認=`承認済`、更新履歴の 反映状況=`承認済`。❌ → 承認=`差戻し`（メモに「片山NG 日付」）。
     どちらも無い候補は保留（そのまま。次回もう一度見る）。
   - 1件でも承認済にしたら `python3 build_slides.py draft --note "承認分の反映: <ID…>"` で **新しい版** を作る。
   - 版管理の承認依頼行のメモを「処理済 / 承認 n件・NG m件・保留 k件」に書き換える（保留が残れば「未処理」のまま）。
3. **前回の巡回日時を調べる**: 版管理タブで 種類=`巡回` の最終行の 生成日時。無ければ 7日前。
4. **新着を読む**（読み取り専用）。2チャンネルだけでなく広く拾う:
   - Slack（主）: `#hawk-社内利用`（C0A276ZULRZ）と `#hawk-product`（C081CRUG68L）の、前回巡回以降のメッセージとスレッド返信を全部読む。
   - Slack（広域）: ワークスペース全体を `slack_search_public_and_private` で検索する。
     クエリ例 `HAWK after:<前回巡回日>`、`HAWK リリース`、`HAWK できる`、`HAWK 仕様`、`DealDesk`、`ディールデスク`。
     #hawk-営業相談（C0ASN8N3JLE）等の他チャンネル・スレッドで出た仕様の回答もここで拾う。DM は読まない。
   - メール: Gmail を `HAWK after:<前回巡回日 YYYY/MM/DD>`（と `DealDesk`）で検索し、リリースノート・
     仕様の回答・お客様からの操作質問を拾う。お客様の個人情報・社名はシートに書かない（機能の可否だけ書く）。
   - Drive（補助）: 前回巡回以降に更新された「HAWK」を名前に含む仕様書・リリースノートがあれば読む。
   - 対象: リリース告知、仕様の「できる/できない」回答、不具合と回避策、提供終了、お客様からよく来る操作質問（→ FAQ・逆引き候補）。
   - 対象外: 日程調整、会食、営業パイプライン、競合の話（HAWK 自身の可否を述べている部分は対象）、
     サービス概要・導入メリット・工数削減・他社比較・料金/契約・セキュリティ（操作ガイドの対象外）。
   - リンクされた Docs/Slides に仕様が書かれていれば `gog docs cat` / `gog slides raw` で読む。
5. **シートに候補として書く**: 追加分をタブごとに TSV（1行目=列名）にして `python3 load_tsv.py <タブ名> <file.tsv>` で追記する。
   （values.append は使わない。チェックボックス列のせいで1000行目付近に書かれてしまう）
   - 新機能 → 機能一覧に新しい機能IDで行を追加。承認=`下書き`。提供状態は告知の文言どおり（リリース済=提供中、開発中/予定はそのまま）。
   - 既存機能の仕様変更 → **承認済の行は書き換えない**。同じ機能IDで新しい行を末尾に追加（承認=下書き）。メモに「旧: …」と差分を書く。
   - 画面が増えた/変わった → サイトマップに同じ要領で追加。「こうしたい→この機能」が読み取れたら逆引きにも追加。
   - すべての変更を **更新履歴** に1行（検知日=今日、リリース日=告知日、ソース=permalink、反映状況=下書き）。
   - 判断がつかないものは **要確認** タブに起票（誰に聞くか: 開発=藤川さん/Ayayaさん、仕様=Yugoさん）。推測で書かない。
   - 書く前に既存行を読み、同じ内容が既にあれば足さない（冪等にする）。
6. **承認依頼を投稿する**（候補が1件以上あるときだけ）:
   - `slack_send_message` で `#hawk-sales-private`（`C0B8HGGC2PJ`）に親メッセージを1件:
     `<@U0B7FMCR8JU> 【HAWKマニュアル】下書きに入れてよいか確認ください（候補 N件）。各候補に ✅（入れる）/ ❌（入れない）を付けてください。次の巡回で ✅ の分だけ下書きの新しい版に反映します。本番には反映しません。`
   - 候補ごとにスレッド返信を1件ずつ: `#1 F-XXX-000 機能名（追加/変更）` ＋ できること1〜2行 ＋ 出典リンク。
   - 版管理タブに `[今日, 今の日時, "承認依頼", "", "", 候補数, "未処理 / ts=<親のts> / #1=F-..., #2=F-..."]` を記録。
7. **巡回記録**: 版管理タブに `[今日, 今の日時, "巡回", "", "", 追加した候補数, "新着N件 / 承認反映M件 / 要確認K件"]`。
8. **報告**（セッションの最終メッセージ）: 反映した承認（ID・機能名）、新しい下書き版の URL、新しく出した候補と承認依頼のリンク、
   要確認の件数。新着も承認反映もなければ「新着なし」の1行だけ。

## 本番に反映する（片山の指示があったときだけ）

1. `python3 housekeep.py`
2. `python3 build_slides.py prod --archive`（URL は変わらない。内容が前回と同じなら PDF 保存はスキップ）
3. 本番 URL と、前回の本番から変わった点を報告する。

## 片山がやること

- `#hawk-sales-private` の承認依頼に ✅ / ❌ を付けるだけ。急ぐときは「承認分を下書きに反映して」と依頼（手順1〜2だけ実行）。
- 本番（お客様の固定URL）に出したいときは「マニュアル本番反映して」と依頼。
- 見せ方（デザイン・文言の型）を変えたいときは `build_slides.py` を直す（テンプレートは1箇所）。

## スクショ

- 片山がスクショ用フォルダ（`screenshot_folder_id`）に画像を置く。名前は何でもよい（Claude が中身を見て「S-xx_画面名.png」に改名する）。
- 生成時に自動で伏せ字加工（`sanitize.py`: OCR でメール・アカウント名・ワークスペース名・人名・広告アカウントID・
  クライアント名等をサンプル表記に置換。画面別ルールは `sanitize_rules.json`）し、「加工済み（自動）」フォルダに保存、
  サイトマップの「スクショ」列に紐づく。スライドへ取り込むときに暗い余白・モーダル背景・白帯を切り落とす（`trim_dark`）。
- 非公開の Drive 画像は Slides API が直接読めないため、pptx 経由で取り込む（`assets.resolve_drive_images`）。
- 加工後は必ず目視確認する（実名・メール・ID・クライアントのブランド名が残っていないか）。

## 注意

- お客様向けの本番版に **開発中・予定の機能は載せない**（提供状態=提供中だけ）。
- これは導入・オンボーディング後のお客様向けの **操作ガイド**。サービス概要・導入メリット・工数削減・
  他社比較・料金/契約・セキュリティ等の FAQ は載せない（承認=差戻し、メモ「操作ガイド対象外」）。
- Slack への書き込みは #hawk-sales-private への承認依頼だけ。マスター以外の Drive ファイルは編集しない。
- 承認列を自分の判断で `承認済` にしない（片山の ✅ か、明示の指示があったときだけ）。
