# HAWK 週報（提案ステータス＋Activity）標準ワークフロー

毎週の「提案ステータス」週タブと「HAWKビジネスプラン」Activityタブを埋める作業を自動化する。
**書き込みは承認後のみ。**ドラフトをチャットに出す→ユーザーが直す→書き込む→読み返して検証、の順を必ず守る。

セル番地・列マッピング・語彙・既知の崩れは `references/sheet-map.md` に全部ある。
**書き込む前に必ずそれを読むこと**（列は増減するのでヘッダー行の実読も併せて行う）。

## 絶対ルール

1. **推測でセルを埋めない。** 出典（議事録Doc名／カレンダーイベント／メール件名／Slack）が取れない項目は空欄にして、ドラフトで「未確認」と明示する。前週の文言を今週の実績のように書き写すのは禁止。
2. **承認前に1セルも書かない。** 収集→ドラフト提示→承認→書き込み。`-n`（dry-run）で意図を見せてから実行してよい。
3. **議事録列は必ず `=HYPERLINK("URL","タイトル")`。** プレーンテキストで上書きするとリンクが死ぬ（既存セルは全部HYPERLINK式）。
4. **既存の値を消さない。** 週タブの引き継ぎは「前週の A〜F を FORMULA で読んで、そのまま書く」。列単位で空文字を流し込むと他人の記入を消す。
5. **Activityの「全体」ブロック（3〜9行）は計画値。触らない。** 個人実績の合計ではない（月初週の列にしか値が入っていない）。
6. gogのグローバルフラグは**サブコマンドの前**（`gog --account ... sheets get ...`）。後ろに置くと `unknown flag`。

- 提案ステータス（週タブの本体）：`1KbOQJCgxaaAzTcQPmOgTjgYl8bCzZrOGyXhKUnK_ESs`
- HAWKビジネスプラン（Activityタブ）：`1S5EB3iEhx3P97_YE6Yx8Kxm_Fwao2Xo_pIpxCaqSB8k`
- HAWKアタックリスト（別物。リード元の確認用）：`1iyhwVNhN_HJNdIBL_pREhrhBdQu2it5ktFOYq-DDm_w`

- 顧客フォルダ：Drive「10_顧客」直下 `<社名>/1_議事録`

## Step 0: 対象週の確定

1. 指定がなければ**直近の月曜はじまりの週**を対象にする。「先週」なら1つ前。
2. 月曜日付から2つのキーを作る：
   - 提案ステータスのタブ名 = `MMDD週`（例: 2026-07-27 → `0727週`）
   - Activityの列 = ヘッダー行の `M/D週`（例: `7/27週`）
3. **列は計算しない。** `Activity!A1:AB1` を読んでラベル一致で列を決める。タブ名も `sheets metadata` で実在を確認する。
4. 対象タブが無ければ `sheets add-tab` で作る（Step 1）。既にヘッダーだけの空タブが先行作成されている場合がある（`0803週`/`0810週` は作成済み。ただし **G1のラベルが前週のまま**なので必ず直す）。

```bash
SS_STATUS=1KbOQJCgxaaAzTcQPmOgTjgYl8bCzZrOGyXhKUnK_ESs
SS_PLAN=1S5EB3iEhx3P97_YE6Yx8Kxm_Fwao2Xo_pIpxCaqSB8k
A=yuki.katayama@fout.jp

gog --account $A sheets metadata $SS_STATUS -p          # タブ実在確認
gog --account $A sheets get $SS_PLAN "Activity!A1:AB1" -p  # 週列の確定
```

## Step 1: 前週タブを引き継いで今週タブを用意

`A〜F`（クライアント名／担当／ステータス／Next Action／In or Out／議事録）は前週から引き継ぎ、
`G`（週コメント）は**空のまま**にして今週の実績だけを新規に書く。`I`（失注理由）も引き継ぐ。

```bash
PREV=0720週 ; CUR=0727週
# 1) FORMULA で読む（HYPERLINK式を保つため必須）
gog --account $A sheets get $SS_STATUS "$PREV!A1:I40" --render FORMULA -j > /tmp/prev.json
# 2) タブが無ければ作る
gog --account $A sheets add-tab $SS_STATUS "$CUR" --index 3
# 3) A〜F と I を書き、G1 に今週ラベル、G2以下は空のまま
#    → values-json で2次元配列を渡す（改行は \n）
```

引き継ぎ時の判断：

- **失注行**は落とさない。「失注ではあるが継続的にご案内していく」系は毎週引き継がれている。
- 今週まったく動きがなかった行も**行は残す**。G列を空にしておく（ドラフトで「動きなし」と申告する）。
- 今週新規で発生した会社は行を追加する。`In or Out` はアタックリストのどのタブ由来かで決める（`references/sheet-map.md` の語彙表）。

## Step 2: 当該週の実績収集（並列可）

サブエージェント（Explore等）に分担させてよい。**収集元と出典の対応を必ず保持する**（ドラフトに出典を書くため）。

| 収集元 | コマンド／方法 | 取るもの |
|---|---|---|
| 議事録Doc | `drive ls --all --query "name contains '議事録_MMDD'"` を週の各日付で。本文は `docs cat` | 実施日・出席者・先方の反応・宿題・次アクション |
| カレンダー | `calendar events --from <月> --to <翌月>` | 商談/デモの実施有無・形式（往訪/オンライン）・同席者。`[オンライン社外]`/`[往訪]`/社名入りイベントが対象 |
| Gmail | `gmail search`（社名・先方ドメイン、当該週） | 送付物・追いかけ・先方返信の温度感 |
| Slack | 社名で検索（public+private） | 社内での言及・注意点 |
| 前週タブのNext Action | `sheets get "$PREV!D2:D40"` | 宿題が消化されたかの突合 |

**議事録Docの選び方**：同じ商談に「（Gemini自動メモ）」版と整形版が両方あることが多い。
**議事録列にリンクするのは整形版**（サイズが小さい方）。Gemini版は本文を読む一次ソースとして使う。

## Step 3: 週タブのドラフト作成

行ごとに以下を埋める。**G列（週コメント）が週報の本体**。

- `ステータス`：`1_導入済` / `2_導入決定` / `3_商談中` / `4_商談中（先方検討中）` / `5_開始` / `失注`（この6値のみ）
- `Next Action`：主語と期日を入れる。複数あるなら `①②③` で並べる（既存行の書き方に合わせる）
- `議事録`：`=HYPERLINK("<docUrl>","<Doc名>")`。複数あれば `／` 区切りで1セルに（既存の本田商事行がその形）
- `G`（週コメント）：`M/D(曜) 実施内容。先方の反応。次の一手。` の順。判断が必要な論点は `【最重要】`/`【開発待ち】`/`【方針一致】`/`【追いかけ】` の見出しを付ける（既存の書式）
- `I`（失注理由）：`失注` にした行は必ず埋める

ドラフトは**表でチャットに出す**。各行に出典を添え、変更がある行だけ「変更前→変更後」を示す。

## Step 4: Activity（KPI件数）のドラフト作成

担当者別ブロック × {初回接触, 商談・デモ実施} × {コールドリスト, 休眠・インバウンド, 紹介} の6セルを埋める。
行番地は `references/sheet-map.md`（各ブロック見出し行 +2/+3/+4 と +6/+7/+8）。

集計ルール：

- **初回接触**＝その週に初めてこちらから接触した件数（メール／電話／メッセンジャー）。既存先への追いかけは数えない。
- **商談・デモ実施**＝その週に実際に実施した商談・デモ・オンボーディングの件数。予定だけの週は数えない。
- カテゴリは会社の `In or Out` から引く（語彙表は `references/sheet-map.md`）。**この対応は暫定**。
- 実施0件は空欄ではなく `0` を入れる（既存が0埋めされている）。

**ドラフトでは必ず「どの会社をどのカテゴリに数えたか」を会社名付きで列挙する。** 数字だけ出すのは禁止。
ユーザーがカテゴリを訂正したら、その訂正を本ファイル末尾の「学習ログ」に追記提案する。

担当者ブロックと `担当` 列（Yuki/Tomo/Miwa）の対応は**確定していない**。
`Activity!A11/A21/A31/A41` を読んでブロック名を出し、ドラフトで対応を明示して承認を取る。

## Step 5: 書き込み

承認後、**batch-update で1リクエストにまとめる**（部分適用の事故を防ぐ）。

```bash
gog --account $A sheets batch-update $SS_STATUS --data-json '[
  {"range":"0727週!A2:F20","values":[[...]]},
  {"range":"0727週!G1","values":[["7/27週"]]},
  {"range":"0727週!G2:G20","values":[[...]]}
]'

gog --account $A sheets batch-update $SS_PLAN --data-json '[
  {"range":"Activity!I13:I15","values":[[0],[1],[2]]},
  {"range":"Activity!I17:I19","values":[[0],[2],[1]]}
]'
```

- 入力は既定の `USER_ENTERED`（HYPERLINK式を式として入れるため必須。`RAW` にしない）
- セル内改行は JSON の `\n`
- 迷ったら先に `-n` を付けて意図だけ出す

## Step 6: 読み返し検証（必須）

書いたら必ず読み返して報告する。

```bash
gog --account $A sheets get $SS_STATUS "0727週!A1:I40" -p
gog --account $A sheets get $SS_STATUS "0727週!F2:F40" --render FORMULA -p   # リンクが式で入ったか
gog --account $A sheets get $SS_PLAN "Activity!I11:I19" -p
```

チェック項目：

- [ ] G1 のラベルが今週になっているか（前週のままになりやすい最頻出ミス）
- [ ] 議事録列が `=HYPERLINK(...)` で入っているか（プレーンテキストになっていないか）
- [ ] 前週にあった行が消えていないか（行数を前週と比較）
- [ ] Activity が正しい列に入っているか（隣の週にずれていないか）
- [ ] `失注` 行の `I` 列が埋まっているか

## 完了報告

- 更新したタブ／セル範囲と、両シートのURLを出す
- 出典が取れず空欄にした項目を「要追記」として列挙する
- 前週のNext Actionのうち未消化のものを「持ち越し」として列挙する

## 外側ループ

実行のたびに、間違えた点（列ずれ・カテゴリ誤分類・担当対応の誤り・拾えなかった収集元）を
本ファイル末尾の「学習ログ」に追記提案する。同じ教訓が3回続いたら手順本体へ昇格させる。
