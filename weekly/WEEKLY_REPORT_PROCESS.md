## 2. 書き込みの作法（Docs API）

- タブ付き Doc なので `gws docs documents batchUpdate` を使う（`gog docs write` はタブ指定不可）。
- 1バッチ内の request は **index 降順**に並べる（前方の挿入で後方の index がずれるため）。
- 表の列追加（`insertTableColumn`）と セル書き込みは**別バッチ**にし、間で `documents.get` を挟む。
- 見出し行は「1セルの表」で作られている。表を探すときは先頭セルの**完全一致**で取る（`ステータス` を部分一致で探すと見出し表を掴む）。
- 箇条書き段落の先頭に挿入すると箇条書きを継承する。ブロック追加は非箇条書き段落（例: `【確度高】`）の先頭に挿入する。
- 強調は `updateTextStyle`（`bold` + `backgroundColor`）。
- 作業用ヘルパー: `weekly/docs_helpers/`（`doclib.py` / `tablelib.py`）。

## 3. 是正点（2026-09-17 時点）

1. **前週コピーの残骸**が毎週残る（ステータス表の週列、5. の「8/31予定」、OEM リストの日付）。
   → 工程1の dump で「前週日付の grep」を必ず行う。将来的には新タブ作成時に日付・週列を機械的に差し替える。
2. **自動ドラフトの出力先が3系統**（日付つき Doc／週報メモ／定例会報告書タブ）。
   → 定例会報告書の当週タブを最終成果物とし、自動ドラフトは「材料」と位置づける（当週タブへの直接上書きは自動では行わない）。
3. **自動ドラフトの提案ステータス参照先が旧アタックリスト固定**。
   → `提案ステータス` シート（`読み管理` と週次タブ）へ差し替える。
4. **全体件数の内訳（5/4/3）が週次で取れない**。
   → 提案ステータス側で「週次スナップショット（全社×ステータス）」を1タブ持つか、棚卸し値を注記付きで載せる運用に統一する。
5. **要望の社数更新が週報とDocで二重管理**。
   → 週報 9. は正本 Doc からの転記のみとし、社数の一次更新は正本 Doc 側（日次 Routine）に寄せる。
6. `読み管理` のヨミには継続ナシ通知済みの社（サイバー・バズ、リソースクリエイション）が残っている。
   → 週報転記時に注記するか、シート側の見直しを Miwa さんと確認する。
