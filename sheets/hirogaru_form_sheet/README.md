# HIROGARU_フォーム入力シート_0817 / 自動追加中リスト_SNS広告求人

外部作業者が **H列(入力状況) / I列(送信日時)** に手入力できるようにするための構成。
対象: https://docs.google.com/spreadsheets/d/1gYL-_-rM52JrWEtsL-Cx-Wv4BPjS49qg9g_n2xq8WqQ/edit?gid=892888463

## 変更前の問題

`自動追加中リスト_SNS広告求人!A1` に配列数式1本（`IMPORTRANGE` + `FILTER`）が入っており、
A1:O 全体がそのスピル範囲だった。よって

- H/I もスピル範囲内なので **どのセルにも手入力できない**
- `FILTER` が「除外リスト / 配信結果csv / 全リスト / 0814 / 0817 に既出の会社」を落とすため、
  会社が処理済みになるたび行が繰り上がる。仮に H:I を数式の外に出しても
  **記入内容が1行ずつズレて壊れる**

このため「A:G と J:O に分けてスピルさせ H:I を空ける」案は採らず、作業シートを静的化した。

## 同期のしくみ（Claude のスケジュール実行 / GitHub Actions）

**現在動いているのは Claude の Routine**（3時間ごとにクラウドセッションを起こして
`sync_new_rows.py` を実行する）。クラウドセッションは SessionStart フックで
gog/gws が自動セットアップされるため、追加の認証設定が要らない。

GitHub Actions 版（下記）も残してあるが、`GOG_*` の Secrets が未登録のため
現時点では動かない。Secrets を入れれば併用できる（同期は会社名で重複排除するので
二重に走っても行は重複しない）。

## 同期のしくみ（GitHub Actions）

`.github/workflows/sync-sns-list.yml` が 3時間おき（UTC の `0 */3 * * *`）に
`sheets/hirogaru_form_sheet/sync_new_rows.py` を実行する。
Apps Script は使っていないので、スプレッドシートのエディタを開く必要はない。

```
gog/gws セットアップ（既存の setup_*_remote.sh を流用）
  ↓
_取込元_SNS広告求人 を読む（#REF! / 読込中 / 0件なら中止）
  ↓
作業シートの B列(会社名) と突き合わせ、未取込の行だけを
A:G と J:O に追記（H:I は書かない）
```

- 認証は Secrets の `GOG_CREDENTIALS_B64` / `GOG_TOKEN_EXPORT_B64` / `GOG_KEYRING_PASSWORD`。
  会社 Mac で `bash sync_gog_token.sh --gh-secrets` を実行すると配布される。
- 手元での確認:
  `python3 sheets/hirogaru_form_sheet/sync_new_rows.py --dry-run`（追記せず件数だけ）
- 手動実行: Actions タブ → このワークフロー → Run workflow（`dry_run` チェック可）
- **cron と Run workflow はデフォルトブランチ上のファイルしか見ない。**
  このブランチをデフォルトブランチにマージするまで定期実行は始まらない。

### 除外リスト（既存顧客・お断り先）の照合

**既存顧客に営業をかけるのが一番まずい**ので、追記の直前に必ず除外リスト
（`除外リスト` タブ / sheetId `785706625` / B列が社名、現在 1,824社）と突き合わせる。

取込元の `FILTER` も `COUNTIF('除外リスト'!B:B, nm)` を見ているが、**COUNTIF は完全一致**
なので表記が1文字違うだけで素通りする。実際に素通りしていた例:

| 取込元の表記 | 除外リスト上の社名 |
|---|---|
| 株式会社電通デジタル 港区 / 大阪市 | 株式会社電通デジタル |
| トランスコスモス株式会社 CX事業統括 サービス推進本部 | トランスコスモス株式会社 |
| パナソニックコネクト株式会社 | パナソニック コネクト株式会社 |
| ADKマーケティング・ソリューションズ | 株式会社ADKマーケティング・ソリューションズ |
| サイバーエージェントグループ / ラクスルグループ | 株式会社サイバーエージェント / ラクスル株式会社 |
| 売れるネット広告社株式会社 | 株式会社売れるネット広告社（前株/後株） |
| 株式会社W‐ENDLESS | 株式会社W-ENDLESS（ハイフンが全角ダッシュ） |
| 株式会社ecbeing | 株式会社ｅｃｂｅｉｎｇ（全角/半角） |

そこで `company_match.py` の正規化照合をもう一段かけている。判定は3つで、
どれかに当たれば**追記しない**（実行ログに理由付きで出す）。

1. **完全一致** … 全角半角・空白・ハイフン・法人格（前株/後株）の差を吸収して一致
2. **拠点・部署付き** … 空白の前が一致し、後ろが「港区」「本部」「採用」等
3. **グループ表記** … 末尾の「グループ」「ホールディングス」を落とすと一致

**似ているだけの別会社は落とさない。** `株式会社LiB` と `株式会社Lib Work`、
`Blue株式会社` と `Blue Zone株式会社`、`株式会社ライト` と `合同会社ライト`
（法人格が違う）は別法人として通す。ロジックは `test_company_match.py` で固定してある
（`python3 sheets/hirogaru_form_sheet/test_company_match.py`）。

除外リストが読めない・100社未満しか読めない場合は**追記せず中止**する
（リストが壊れたまま全通しになるのを防ぐ）。

なお **社名変更・親子会社は文字列では分からない**（例: `dely株式会社` は 2025-10-01 に
`クラシル株式会社` へ社名変更、`株式会社D2C R` は `株式会社D2C` の子会社）。
これは自動判定できないので、気づいたら除外リストに社名を足すこと。

### 会社名の突き合わせ

キーは会社名(B列)で、**空白を全て除去して比較**する。取込元には
`株式会社CARTA HOLDINGS` / `株式会社CARTAHOLDINGS` のように空白違いの同一企業が
実在するため（2026-08-24 時点で6組）、空白を無視しないと同じ会社が二重に入る。

### 途中で止まる条件（事故防止）

- 取込元が `#REF!` / `#N/A` / 読込中
- 取込元の1行目が期待する列構成（`EXPECTED_HEADER`）と違う
- 取込元がまったく空（IMPORTRANGE の数式が消えた）
- sheetId のタブが見つからない（削除された）

**有効行0件は異常ではない**。取込元は `FILTER` で既出企業を落とすので、
全部処理済みならヘッダーだけになる。この場合は「新着なし」として正常終了する。

## 取得日(G列) について

取込元のクロールが日付を**シリアル値のまま（書式なし）**書いている行があり、
source 側の表示も `46255` のような数字になっている（2026-08-24 時点で末尾20行ほど）。
作業シート側は G列に `yyyy-mm-dd` の表示形式を当てて読めるようにしたが、
**文字列の日付と数値の日付が混在**しているのは変わらないので、
日付での並べ替え・絞り込みをしたいならクロール側の出力を揃えるのが本筋。

## 保守メモ

- 除外リストのタブを作り直したら `sync_new_rows.py` の `EXCLUDE_SHEET_ID` を更新する。
- 列を増やす場合は `sync_new_rows.py` の `LAST_COL` と `WRITE_BLOCKS` を更新する。
  H(8)・I(9) が `WRITE_BLOCKS` に入らないよう注意すること。
- 移設時に `IMPORTRANGE` の範囲を `フォーム送信用!A2:R3000` → `A2:R`（開放端）に変更した。
  取込元が3000行を超えても取りこぼさない。
- `backup/` に変更直前の値と数式のスナップショットがある（2026-08-24）。
- トークンが失効すると Actions が失敗する。復旧は会社 Mac で
  `bash sync_gog_token.sh --reauth`（CLAUDE.md の運用ルールどおり、認証は1台だけ）。
