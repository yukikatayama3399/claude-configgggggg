# 窓口セッション と 返信見張り（2026-11-25 片山さん決定）

話題ごとにセッションを分けずに投げているので、「あの件どこで話してたっけ」「返信が来た件はどのセッション？」に
最短でたどり着くための仕組み。

## 構成

| 役割 | 実体 | 中身 |
|---|---|---|
| 窓口セッション | `session_01Rtp7SG5rSQjo2qvqGB64j8`（タイトル「📌 窓口」、Sonnet） | 左のサイドバーで**片山さんが手動でピン留め**する。「〇〇の件どこ？」に、該当セッションのリンク付きで答える |
| 返信見張り | 定期実行 `trig_01Hwo3M968VTUWreRRV48wn9`（平日 8:00〜21:00 JST の毎時、**窓口セッションの中で実行**） | Gmail（と使えれば Slack）の新着を見て、過去セッションへの返信なら、そのセッションのタイトル先頭に「🙋 」を付けて窓口に対応待ち一覧を出す。手順は窓口のシステムプロンプト（作成時の append_system_prompt）に入っている |

## 🙋 の意味

**「片山さんが動く番」のセッションだけ**に付ける（検索で見つけただけのものには付けない）。
増えすぎると今のポップアップと同じで見なくなるため。

- 付ける: 返信見張りが、メール/Slack の返信とセッションを**確信を持って**紐付けられたときだけ
- 外す: 窓口で「〇〇済」「全部済」と言う／そのセッションで会話を再開すると、窓口が次に一覧を作るときに外す

## 🙋 を付けない場合（2026-11-25 片山さん決定）

- 片山さんがすでに返信し、担当者へのバトンタッチが済んでいるスレッドの返信には付けない
  （例: ACE スレッドで酒井さんが小瀬さん宛てに見積もりIDを返信 → 片山さんの番ではない）
- 判断: 宛先が片山さん本人か／片山さんの返信・判断を求める内容か／スレッドの最新が片山さん本人でないか
- 同じ相手から片山さん宛てに別用件が来たら付け直し、一覧に「やること: ○○」を添える。迷ったら付けずに「判断に迷った」と書く
- このルールは定期実行 `trig_01Hwo3M968VTUWreRRV48wn9` の指示文に入れる。
  **定期実行の指示文は、実行先の会話（＝窓口）からしか変更できない**（`update_trigger` が他の会話からだと拒否される）ので、窓口で頼む。

## 窓口での言い方

- 「〇〇の件どこ？」 → 候補セッションをリンク付きで最大5件
- 「今チェックして」「返信来てる？」 → 窓口がその場で返信見張りを実行（既定は直近3時間）
- 「一覧」「対応待ち」 → 今 🙋 が付いているセッションの一覧
- 「〇〇済」「全部済」 → 🙋 を外す

## 分かっている制約（2026-11-25 実測）

- **タイトルを変えても一覧の並び順は上がらない**（`updated_at` が変わらない）。だから窓口に一覧とリンクを出す方式にした。
  窓口は報告を受けるたびに更新されるので、ピン留めしていなくても上に来る。
- **窓口から別のセッションを直接開くことはできない**（開けるのは自分が立ち上げたセッションだけ）。リンク `https://claude.ai/code/<session_id>` をタップして飛ぶ。
- **クラウドの定期実行は最短1時間おき**（10分おきは `the minimum interval is 1 hour` で拒否された）。
  メール着信に即反応する仕組み（Gmail のプッシュ通知）はこの環境では受けられない。
  → 1時間おきの自動チェック＋窓口での手動チェックで補う。
- **定期実行に Slack コネクタを持たせられない**（`connectors parameter is not available for this organization`）。
  Slack が読めない回は結果の末尾に「(Slack未確認)」が付く。Gmail は gog で読むので影響なし。
- **「毎回新しいセッション」型の定期実行には、セッション一覧・タイトル変更の道具が無い**（2026-11-25 のテストで判明）。
  だから見張りは窓口セッションの中で動かす（`persistent_session_id` で窓口に向けた定期実行）。
- **窓口は、別セッションから送られてきた指示を設定として取り込まない**（安全上の正しい動き）。
  窓口の役割を変えたいときは、片山さんが窓口に直接言うか、窓口を作り直す（役割は作成時のシステムプロンプトで固定）。

## 安全面

- 返信見張りはメール・Slack を**読むだけ**（gog は `--gmail-no-send`）。他のセッションに対して行うのはタイトル変更だけで、
  send_message はしない。送信の絶対ルール（CLAUDE.md 冒頭）に抵触しない。
- 定期実行の指示文は「窓口のシステムプロンプトの (B) を直近75分で実行」だけ。手順本体を変えるなら窓口を作り直す。
