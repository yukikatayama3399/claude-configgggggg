# 窓口セッション と 返信見張り（2026-11-25 片山さん決定）

話題ごとにセッションを分けずに投げているので、「あの件どこで話してたっけ」「返信が来た件はどのセッション？」に
最短でたどり着くための仕組み。

## 構成

| 役割 | 実体 | 中身 |
|---|---|---|
| 窓口セッション | `session_01Rtp7SFvrwzRqmzW4kofPJ7`（タイトル「📌 窓口」、Sonnet） | 左のサイドバーで**片山さんが手動でピン留め**する。「〇〇の件どこ？」に、該当セッションのリンク付きで答える |
| 返信見張り | 定期実行 `trig_01UsJKhrYmbp8Q5neAXoZDSS`（平日 8:00〜21:00 JST の毎時0分、Sonnet、毎回新しいセッション） | Gmail（と使えれば Slack）の新着を見て、過去セッションへの返信なら、そのセッションのタイトル先頭に「🙋 」を付けて窓口に報告 |

## 🙋 の意味

**「片山さんが動く番」のセッションだけ**に付ける（検索で見つけただけのものには付けない）。
増えすぎると今のポップアップと同じで見なくなるため。

- 付ける: 返信見張りが、メール/Slack の返信とセッションを**確信を持って**紐付けられたときだけ
- 外す: 窓口で「〇〇済」「全部済」と言う／そのセッションで会話を再開すると、窓口が次に一覧を作るときに外す

## 窓口での言い方

- 「〇〇の件どこ？」 → 候補セッションをリンク付きで最大5件
- 「今チェックして」「返信来てる？」 → 返信見張りをその場で実行（`fire_trigger`、既定は直近3時間）。数分で結果が窓口に届く
- 「一覧」「対応待ち」 → 今 🙋 が付いているセッションの一覧
- 「〇〇済」「全部済」 → 🙋 を外す

## 分かっている制約（2026-11-25 実測）

- **タイトルを変えても一覧の並び順は上がらない**（`updated_at` が変わらない）。だから窓口に一覧とリンクを出す方式にした。
  窓口は報告を受けるたびに更新されるので、ピン留めしていなくても上に来る。
- **窓口から別のセッションを直接開くことはできない**（開けるのは自分が立ち上げたセッションだけ）。リンク `https://claude.ai/code/<session_id>` をタップして飛ぶ。
- **クラウドの定期実行は最短1時間おき**（10分おきは `the minimum interval is 1 hour` で拒否された）。
  メール着信に即反応する仕組み（Gmail のプッシュ通知）はこの環境では受けられない。
  → 1時間おきの自動チェック＋窓口での手動チェックで補う。
- **定期実行に Slack コネクタを持たせられない**（`connectors parameter is not available for this organization`）。
  Slack が読めない回は結果の末尾に「(Slack未確認)」が付く。Gmail は gog で読むので影響なし。

## 安全面

- 返信見張りはメール・Slack を**読むだけ**（gog は `--gmail-no-send`）。他のセッションに対して行うのはタイトル変更だけで、
  send_message は窓口宛てのみ。送信の絶対ルール（CLAUDE.md 冒頭）に抵触しない。
- 指示文を変えるときは `update_trigger` の `prompt`。この README の内容と揃えておく。
