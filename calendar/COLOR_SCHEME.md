# カレンダー色分け・命名の統一設計（2026-09-02 見直し版）

対象カレンダー: yuki.katayama@fout.jp

## 色の設計（4色だけ。これが正）

| 色 | colorId | 意味 |
|---|---|---|
| グレー（グラファイト） | 8 | **作業**。一人の作業ブロック・準備・メモ書き・事務 |
| オレンジ（タンジェリン） | 6 | **オンラインミーティング**（社外・社内問わず） |
| 紫（グレープ） | 3 | **実際に外出する予定・対面・オフライン**。往訪/来訪/対面の社内MTGに加え、**ランチ・会食・夜の外出・飲み・通院・ジムなど外出を伴う私用も紫** |
| 赤（トマト） | 11 | **その他・関係ないもの**。カレンダーの既定色が赤なので「色なし」と見た目が同じ。間違った色が残っている予定だけ明示的に赤(11)で上書きして直す |

2026-09-02 の見直しポイント:
- 旧設計では「ランチ・会食・私用」を色なし（デフォルト）にしていたが、
  **外出を伴う私用は紫**に変更（実際に外出する予定はすべて紫、が原則）。
- 旧設計は「デフォルトに戻す＝色を消す」ができない API 制約で
  手動クリアをお願いしていたが、**既定色＝赤なので赤(11)を明示的に塗れば同じ見た目**になり、
  間違った色の残りも自動で直せるようになった。

## 命名（主タグ）との対応

命名Routineが付ける主タグは7つのみ: 往訪 / 来訪 / オンライン社外 / 社内 / オンライン社内 / 作業 / Private。
**これ以外のタグを発明しない**（[オフライン社内]のような変種を作らない。対面の社内MTGは[社内]）。

| 主タグ | 色 | availability |
|---|---|---|
| [作業]（[準備]も作業扱い） | グレー 8 | FREE |
| [オンライン社外] [オンライン社内] | オレンジ 6 | BUSY |
| [往訪] [来訪] [社内]（過去の変種 [社外] [オフライン*] も同じ） | 紫 3 | BUSY |
| [Private] 外出系（ランチ・会食・飲み・通院・ジム等） | 紫 3 | FREE |
| [Private] その他・関係ないもの | 赤 11（=既定色のまま） | FREE |

タグが無い予定はスクリプトがキーワード・出席者から推定する（推定は必ず報告に出る）:
- 外出キーワード（ランチ/会食/飲み/通院/ジム…）→ 紫
- タイトルに「オンライン」等 → オレンジ
- 他の出席者がいる → 紫（対面に倒す）
- 「準備」「メモ」等の作業キーワード → グレー
- 会議らしいタイトルだが対面/オンライン不明 → **触らず要タグ付けとして報告**
- 推定でグレーにしようとした予定に既にオレンジ/紫が付いている → **触らず報告**（手動の意図を尊重）

## 実行の仕組み（Routine 2本立て）

1. **カレンダー命名＆予定あり/なし仕分け**（毎日 9:00 / 15:00 JST, MCPコネクタ使用）
   タイトルに主タグを付け、availability を直す。色は触らない。
2. **カレンダー色分けスイープ**（毎日 9:20 / 15:20 JST, gog使用）
   命名の直後に走り、タグに従って色だけを塗る。
   判定は `calendar/color_sweep.py`（このリポジトリが正本）が決定論的に行う。
   **Routineのプロンプトにも同じスクリプトが埋め込まれているので、直すときは両方更新する。**

手動で回す場合（このリポジトリのクローン内で）:

```bash
python3 calendar/color_sweep.py           # ドライラン（読み取りのみ）
python3 calendar/color_sweep.py --apply   # 適用（書き込み後に読み返し検証）
```

## 判定に使ってよい材料・いけない材料

- ✅ タイトル先頭の `[主タグ]`、タイトル中のキーワード
- ❌ Meetリンク・会議室リソース・location（2026-08-22 実測で、
  会議室を押さえていてもオンライン／Meetリンクがあっても対面のケースが両方ある）
