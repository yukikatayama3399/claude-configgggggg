# ステップ0: 準備確認
このセッションにはリポジトリがあり、起動時のフックで gog がセットアップ済み（外部から clone はしない）。
Bash は毎回、リポジトリ直下で先頭に `export PATH="$HOME/bin:$HOME/.local/bin:$PATH" && ` を付けて実行する。
`gog auth doctor --check --no-input` が失敗したら `bash setup_gog_remote.sh` を1回だけ試す。それでも失敗したら、カレンダーには一切触れず「🎨 gog不調のため色分けを中止: <エラー要旨>」と Slack DM に1行送って終了。gog auth add は絶対に叩かない。

# ステップ1: ドライラン → 本実行
```bash
python3 calendar/color_sweep.py                       # 読み取りのみ
python3 calendar/color_sweep.py --apply > /tmp/color_report.txt 2>&1; cat /tmp/color_report.txt
```
ドライランで変更対象が20件を超えた場合は `--apply` せず、ドライランの出力（DRY 行）をそのまま付けて
「🎨 カレンダー色分け: 変更対象が多い（N件）ため未適用。問題なければこのセッションに『色分け適用OK』と返信してください」と Slack DM で通知して終了する（黙って終わるのは禁止）。
片山さんがこのセッションで『色分け適用OK』と返信してきたら、その時点で `--apply` を1回だけ実行して結果を DM する。

# ステップ2: 通知（Slack DM・1回だけ）
本文はスクリプト出力の数字をそのまま使う:
```
🎨 カレンダー色分け（YYYY/MM/DD JST）
適用 N件 / 失敗 N件 / 未反映 N件
（変更した予定を1行ずつ。仮予定を黄にしたものは「仮 6→5」のように分かる形で）
▼推定で決めた予定（タグなし・要タグ付け）
▼触らなかった予定（黄/会議色と衝突・要タグ付け）
```
適用0件・推定0件・衝突0件の日は DM を送らずに終わる。一度送信に成功したら再送しない。Slack 送信が失敗してもメールに切り替えない。
日付は `TZ=Asia/Tokyo date +%Y/%m/%d`。
禁止: colorId 以外の変更（削除・時間・タイトル・出席者）、コミット・プッシュ。最終回答は「適用N件」程度の1行にする。
